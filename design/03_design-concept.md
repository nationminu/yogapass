## 1. 이번 개정이 무엇을 바꾸고 무엇을 바꾸지 않는가

### 1.1 배경

| 항목 | 내용 |
|---|---|
| 계기 | CR-002 (2026-09-13 PM 지시) — "디자인은 너무 부족한데 최신 트랜드를 반영해서 다시 지시해라" |
| 이 산출물의 용도 | **내부 검증본이 아니라 PM이 고객에게 직접 보여줄 물건이다.** "기준을 충족한다"가 아니라 **"좋다"** 는 반응이 목표다 |
| v1.0과의 관계 | v1.0의 3안(A 정돈된 신뢰 / B 고요한 호흡 / C 또렷한 안내)과 PM의 **시안 A 선택(2026-09-12)은 폐기하지 않는다.** 이번 v2.0은 그 **위에 얹는 시각 언어 고도화**이며, 방향안 ⓐ는 시안 A의 직계 후속이다 |

### 1.2 designer가 진단한 "디자인이 부족하다"의 원인 4가지

PM 판정을 그대로 받되, 원인을 특정하지 않으면 같은 결과가 반복된다. 현행 v1.x 화면을 다시 보고 아래 4가지로 정리했다.

| # | 원인 | 증상 | v2.0에서의 처방 |
|---|---|---|---|
| **D-1** | **타이포 스케일이 작다** | 데스크톱 h1이 46px에 불과해 첫 화면의 시각적 무게가 없다. "잘 정리된 문서"처럼 읽히고 "브랜드"로 읽히지 않는다 | **display 74px** 신설(§3.2). 두께 대비(300↔800)·자간 −0.028em·행간 1.04로 조판 자체를 그래픽으로 만든다 |
| **D-2** | **면(surface)이 흰색 하나뿐이다** | 흰 배경 + 1px 선 + 8px radius 카드만 있어 화면에 층이 없다. 스크롤해도 리듬이 생기지 않는다 | **4층 면 체계**(흰색 / 모래 / 스톤 / 딥 네이비) + **그라데이션 히어로 + 노이즈 결**(§3.1·§3.4) |
| **D-3** | **움직임이 0이다** | v1.x는 "페이지 전환 애니메이션 없음 · 스크롤 등장 효과 쓰지 않는다"로 명시했다. 안전하지만 2026년 기준으로는 **완성되지 않은 화면으로 읽힌다** | **스크롤 진입 리빌 · hover 부유 · 키네틱 밑줄**을 넣되, **LCP 요소에는 애니메이션을 걸지 않는다**는 규칙과 **개발팀 금지선 22항**으로 성능을 보호한다(§3.5) |
| **D-4** | **사진이 0장이다** | 웰니스 업종 레퍼런스의 밀도는 대부분 사진에서 나온다. 사진 없이 v1.x 방식(라인 격자 1개)으로는 히어로가 비어 보인다 | 사진을 대신할 **7가지 수단**을 실제로 구현했다(§4). 동시에 **사진 없이 도달 가능한 한계선**을 §4.3에 정직하게 적었다 |

> **D-1~D-3은 v2.0에서 해소된다. D-4는 절반만 해소된다.** 그 선을 §4.3에 명시했다.

## 2. 세 방향안의 공통 골격 (먼저 읽어 주십시오)

### 2.1 다른 것은 색뿐이다

```
┌──────────────────────────────────────────┐
│ 색 레이어      ← ⓐ / ⓑ / ⓒ 로 갈린다 (16개 토큰)   │
├──────────────────────────────────────────┤
│ 타이포 스케일 · 간격 · radius · shadow · 모션 · 그리드 │  ← 공통 (1벌)
│ 컴포넌트 46종 구조 · 상태 · 접근성 규칙              │  ← 공통
└──────────────────────────────────────────┘
```

- 방향 선택은 **디자인 시스템의 §1.1(컬러)만** 바꾼다. §1.2~§1.6과 §2·§3(컴포넌트)은 그대로다.
- 따라서 **선택이 늦어져도 나머지 작업은 진행할 수 있고**, 선택이 바뀌어도 재작업은 **색 토큰 16개 교체 + 대비표 재계산(0.5작업일)** 이다.
- 이 구조 자체가 K-7(2차 45화면)에 대한 답이다.

### 2.2 세 방향 공통 — 2026 트렌드 적용분

| 트렌드 (근거) | 이 프로젝트에서의 구현 | 적용 범위 |
|---|---|---|
| **뮤트 팔레트** (요가 스튜디오 상위 사이트의 84%) | 세 방향 모두 **채도 높은 원색을 면에 쓰지 않는다.** 유채색은 CTA·링크·포커스에만 등장한다 | 전 화면 |
| **2~3 자연색 + CTA 전용 강조색 1개** | ⓐ 모래·크림·하늘빛 + CTA 블루 / ⓑ 크림·세이지·모래 + CTA 세이지 / ⓒ 종이·잉크 + CTA 블루 | 전 화면 |
| **일출·해질녘 그라데이션 배경** | 히어로·페이지 헤더·CTA 밴드에 **3-stop 그라데이션 + 라디얼 2겹**. 텍스트 대비는 **가장 어두운 정지점 기준으로 판정**한다(디자인 시스템 §1.1 ⑤) | 히어로·페이지 헤더·밴드 |
| **오버사이즈 헤드라인 + 넉넉한 본문 여백** | display 74px / 섹션 간격 120px(데스크톱) / 본문 행간 1.72 | 1차 소개형 화면 |
| **키네틱 타이포그래피** | 히어로 헤드라인 **밑줄 스윕**(280ms 1회, 헤드라인 글자 자체는 즉시 렌더) — **화면당 1곳뿐** | SCR-001 히어로 |
| **가변 폰트** | **채택하지 않는다.** 굵기를 **2단(400·700)** 으로 고정했다 → §3.2 ② |  |
| **절제된 모션·부유 아이콘·차분한 진입 전환** | 스크롤 리빌 · 카드 6px 부유 + 아이콘 −4° 회전 · 버튼 2px 상승 | 전 화면 |
| **모바일 65% · 접힘선 위 CTA · 상시 전화 노출 · 스티키 예약 버튼** | v1.x에서 이미 충족(G-1·G-5·G-8 하단 고정 바 + 헤더 전화). 이번에 **히어로 CTA 도달 높이를 재계산**해 360×640에서 여유 35px을 확보했다(§3.3) | 전 화면 |

## 3. 세 방향 공통 — 시각 언어 v2.0

### 3.1 면(surface) 4층 체계 — D-2의 처방

v1.x는 흰 면 하나에 선만 그었다. v2.0은 **네 층**을 번갈아 써서 스크롤에 리듬을 만든다.

| 층 | 역할 | 쓰는 곳 | ⓐ의 값 |
|---|---|---|---|
| L0 **베이스** | 기본 본문 면 | 일반 섹션, 카드 내부 | `#FFFFFF` |
| L1 **웜 서피스** | 한 단계 낮은 면 | 강점·정보 섹션 | `#FAF7F2` 모래 |
| L2 **스톤** | 두 단계 낮은 면 | 강사·보조 섹션 | `#F1ECE3` |
| L3 **딥** | 반전 면 | CTA 밴드, 푸터, 마퀴 스트립 | `#0E1C2B` |
| **G** 그라데이션 | 진입 면 | 히어로, 페이지 헤더 | `L1 → L2 → 틴트` 3-stop + 라디얼 2겹 + 노이즈 5% |

**규칙 3가지**
1. **같은 층을 연속 두 섹션에 쓰지 않는다.** 스크롤 리듬이 죽는다.
2. **L3는 한 화면에 최대 2회**(CTA 밴드 + 푸터). 더 쓰면 PM 원 지시("무겁지 않게")를 넘는다.
3. **그라데이션 위 텍스트는 가장 어두운 정지점 기준으로 대비를 판정한다.** 이 규칙이 뮤트 팔레트에서 대비가 무너지는 것을 막는 유일한 장치다.

### 3.2 타이포그래피 — D-1의 처방

**① 스케일을 한 단 올린다** (상세 표는 디자인 시스템 §1.2)

| | v1.x | **v2.0** | 변화 |
|---|---|---|---|
| 히어로 display (≥1280px) | 46px | **74px** | +61% |
| h1 (하위 화면, ≥1280px) | 46px | **52px** | +13% |
| h2 (≥1280px) | 32px | **40px** | +25% |
| 본문 (≥1280px) | 16px | **17px** | +6% |
| 본문 (<768px) | 15px | **16px** | +7% (모바일 가독성) |
| 섹션 간격 (≥1280px) | 96px | **120px** | +25% |

**② ★ 굵기는 2단(400 · 700)으로 고정한다 — 가변 폰트로 전환하지 않는다** (TKT-DEV-001 §C 회신)

개발팀 실측: 현행 전송량의 **81%가 폰트**(메인 198KB 중 160KB)다. 가변 전환 시 181KB(+13.5%)·**LCP +144ms**이고, **굵기를 3단 이상 쓰기 시작하면 그때부터 가변이 17~26% 싸진다.** 즉 결정 변수는 "굵기 단 수" 하나다.

**designer 결정: 2단(400·700) 유지.**

| 근거 | 설명 |
|---|---|
| ① 크기가 대비의 절반을 만든다 | display **74px**에서 `400 ↔ 700` 대비는 이미 충분히 강하다. 34px 본문이었다면 300이 필요했겠지만 display는 **크기 자체가 위계를 만든다** |
| ② 공수 0일 · LCP 유지 | 전환 공수 0일, LCP 1,060ms 유지. PM 방침 "최대한 빨리" + 개발팀 A→B→C 분할 권고에 그대로 맞는다 |
| ③ **CLS 0을 지킨다** | 폴백 서체 메트릭 정의가 400·700 두 개뿐이다. 중간 굵기(500·600)를 넣으면 웹폰트 로딩 중 줄바꿈이 흔들려 **현행 CLS 0이 깨진다.** 300·800의 시각 이득이 이 위험을 넘지 못한다 |
| ④ 전환 시점을 2차로 옮긴다 | 2차 45화면(관리자·데이터)에서 굵기 요구가 3단 이상으로 늘어나면 그때 가변이 더 싸진다. **결정을 미루는 것이 아니라 판단 근거가 확정되는 시점으로 옮기는 것**이다 |
| ⑤ 가변축 애니메이션 리스크 소멸 | 가변이 없으면 wght 애니메이션(전 제목 적용 시 **드롭 프레임 25.2%**)이라는 함정 자체가 없어진다 |

**따라서 개성은 아래 4수단으로 만든다 — 폰트 파일 증가 0KB.**

| 수단 | 구현 | 비용 |
|---|---|---|
| **한 헤드라인 안에서 두께를 섞는다** | `하루 한 번,`(**400**, `--color-ink-2`) + `숨이 느려지는 시간`(**700**, `--color-ink`) | **0** — 이미 로드된 2단 |
| **자간을 크기별로 다르게 잡는다** | display −0.028em / h1 −0.030em / h2 −0.028em / 본문 0 | 0 |
| **행간을 크기에 반비례** | display 1.04 / h1 1.14 / h2 1.16 / 본문 1.72 | 0 |
| **`text-wrap: balance`** | 헤드라인 줄바꿈을 브라우저가 균형 배분 | 0 (미지원 브라우저는 기본 줄바꿈) |

> **부수 효과 하나**: 방향안 ⓑ의 초안에 있던 **명조 제목(Nanum Myeongjo)도 폐기**했다. 제목용 한글 서체 1벌 추가 = 화면당 **+100KB 이상**(TKT-DEV-001 A-9). ⓑ의 업종 정체성은 이제 **색 + 아치 마스크 + pill 곡률**로만 만든다. 그 결과 **세 방향안의 폰트 비용이 완전히 같아졌고**, 방향 선택이 성능에 영향을 주지 않는다.
> `--fw-medium: 500`은 v1.x와 같이 **1차·2차 모두 미사용**이다.

**③ 최소 크기 하한은 그대로다.** 문장 14px, 입력 필드 16px(iOS 자동 확대 방지). 오버사이즈는 위로만 간다.

**④ 전역 규칙 (K-8)**
- `prefers-reduced-motion: reduce`에서 **전 duration 0.01ms + `animation-timeline: none !important` + `scroll-behavior: auto`**.
  → **스크롤 연동 애니메이션은 진행률이 시간이 아니라 스크롤 위치로 결정되므로 duration만으로는 꺼지지 않는다**(A-3). 모션 토큰 `--motion-scroll`·`--motion-kinetic`·`--motion-parallax-distance`도 0이 된다.
- **애니메이션 대상은 `opacity`·`transform`뿐이다.** `width`·`height`·`top`·`margin`·`font-size`를 애니메이션하지 않는다(A-1 #3).
- **헤더·하단 고정 바는 스크롤에 따라 숨거나 높이가 변하지 않는다**(A-1 #6 — G-9·G-10 실측 로직 보호).
- **페이지 전환 애니메이션은 여전히 만들지 않는다.**
- **인라인 스타일을 전제한 연출을 만들지 않는다**(A-8 · CSP · DEF-003 재발 방지).

**⑤ LCP 보호 규칙 (가장 중요)**
> **히어로의 h1 · lead · 주 CTA에는 어떤 진입 애니메이션도 걸지 않는다.**
> `opacity:0`에서 시작하는 요소는 브라우저가 "렌더되지 않은 것"으로 보아 LCP가 애니메이션 종료 시점까지 밀린다. 스크롤 리빌(`.rv`)은 **첫 화면 아래 요소에만** 붙인다.

**⑥ 모션 품질은 Lighthouse로 판정할 수 없다**
> 개발팀 실측: **스크롤 중 프레임의 25%를 떨어뜨린 구성도 Lighthouse 성능 100**이 나왔다. Lighthouse는 로딩 구간만 측정하기 때문이다.
> 따라서 모션 판정 기준은 **"360×640 · CPU 4배 스로틀 · 4000px 스크롤에서 드롭 프레임 0%"** 하나이며, 측정은 P4(developer)·P5(qa)에서 한다. **designer는 측정하지 않았다.**

### 4.2 사진이 들어올 자리 — 5개소 · 촬영 지침

**PM이 고객에게 이 표를 그대로 전달할 수 있게 썼다.**
**5개소 모두 "사진이 들어와도 레이아웃이 바뀌지 않는다."** 현재는 같은 비율의 그래픽 패널이 들어가 있고, 교체만 하면 된다.

| ID | 위치 | 비율 | 최소 해상도 | 안전 영역 | 필요 장수 | 촬영 지침 |
|---|---|---|---|---|---|---|
| **P-1** | SCR-001 히어로 아트 패널 | **4:3** | **1600×1200** | 중앙 70% 안에 피사체. 좌하단 24% 영역은 라벨이 덮을 수 있다 | 1 | **스튜디오 내부 전경.** 자연광, 사람은 실루엣이거나 2명 이하. 강한 원색 소품 배제(뮤트 팔레트와 충돌). 가로 촬영 |

**공통 촬영·납품 지침**
1. **가로 촬영** 기본(P-3 제외). 세로 원본은 크롭 손실이 크다.
2. **원본 그대로** 주십시오. 스마트폰 보정 필터·문자 삽입본은 쓸 수 없다. 압축·포맷 변환(AVIF/WebP)은 개발팀이 한다.
3. 1장당 **최종 200KB 이하**로 압축한다(성능 기준). 원본은 크게 주셔도 된다.
4. **색감**: 따뜻한 자연광. 형광등 아래 차가운 색은 이번 팔레트(모래·크림)와 충돌한다.
5. **사람이 식별되는 사진은 초상권 동의서를 함께** 주십시오. 없으면 사용하지 않는다.
6. **스톡 사진을 쓸 경우**: 상업적 사용 + 웹 배포 허용 라이선스만. 출처·라이선스·취득일을 `design/assets/SOURCES.md` §4에 기록해야 한다. **인물 스톡으로 강사를 대체하는 것은 금지**(화면정의서 SCR-002 §3).

### 4.3 ★ 사진 없이 도달한 수준과, 사진이 있어야 넘는 선 (PM께 정직하게)

| 구분 | 현재(사진 0장)에서 도달한 것 | 사진이 들어와야 넘을 수 있는 선 |
|---|---|---|
| **첫인상** | "정돈되고 세련된 브랜드 사이트"까지는 간다. 타이포·그라데이션·여백으로 만든 인상이다 | **"이 공간에 가 보고 싶다"는 감정**은 만들 수 없다. 공간감·분위기·온도는 사진의 영역이고 그래픽으로 치환되지 않는다 |
| **신뢰** | 정보 구조·명료함으로 "제대로 만든 곳"이라는 신뢰는 만든다 | **"실재하는 스튜디오"라는 신뢰**는 부족하다. 방문 전환(오프라인 유입)에서 실제 공간 사진의 효과는 그래픽이 대체하지 못한다 |
| **강사 소개(SCR-002)** | **가장 약한 화면이다.** 이니셜 카드 3장은 "정보가 아직 없는 화면"으로 읽힌다 | 강사 얼굴 사진 1장씩(P-3)만 들어와도 이 화면의 완성도가 가장 크게 오른다. **투자 대비 효과 1순위** |
| **수업 유형** | 기하 심볼 + 난이도 표시로 "무엇이 있는지"는 전달된다 | 동작 컷(P-2)이 들어오면 "어떤 느낌의 수업인지"가 전달된다 |
| **업종 정체성** | 색·곡률·여백으로 "웰니스 계열"임은 읽힌다 | **"요가 스튜디오"라는 즉각적 인지**는 사진이 가장 빠르다 |

> **designer 판단 — 우선순위**
> 사진이 끝까지 0장이어도 **1차 오픈은 가능하다.** 위 7수단으로 "부족해 보이는" 상태는 넘어섰다.
> 다만 **P-3(강사 1:1) → P-1(스튜디오 전경) → P-2(수업 동작)** 순으로 확보하면 완성도가 눈에 띄게 오른다.
> **P-3만 확보해도 체감 개선의 절반 이상**이 온다. 스마트폰으로 같은 벽 앞에서 같은 구도로 찍은 것이면 충분하다.
> 이것은 `[TBD: 고객 확인 필요]` 항목이며, `pm/01_project-plan.md` Q11(사진 조달 방침) 미회신 상태다.

| 차별화(다른 요가 사이트와의 구분) | 중 | 중 | **최상** |

### 6.2 designer 권고 — **ⓐ 고요한 신뢰**

근거 (우선순위 순):

1. **고객이 명시한 것을 designer가 뒤집을 근거가 부족하다.** 고객 원문은 "화이트·블루로 신뢰감 있게"다. 트렌드 데이터는 업종 일반론이고, 이 고객의 브랜드 의도가 아니다. **ⓑ로 가려면 고객 동의가 먼저**이고, 그 동의를 얻기 전에 상세 디자인을 세이지로 진행하면 되돌릴 때 비용이 든다.
2. **"디자인이 부족하다"의 원인은 색이 아니었다.** §1.2 진단 D-1~D-3(작은 타이포·단층 면·모션 0)은 **색과 무관**하다. 이 셋을 고치면 ⓐ에서도 인상이 크게 바뀐다 — 목업 `concept-2a.html`이 그 증거다. 색을 바꾸는 것은 가장 눈에 띄지만 원인 해결은 아니다.
3. **2차가 진짜 무게중심이다.** 1차 6화면 : 2차 39화면. 2차 대부분이 캘린더·표·폼·배지다. 블루·네이비 계열은 이 영역에서 가장 검증된 조합이고, 세이지는 밀도가 올라갈수록 탁해진다.
4. **일정.** PM 방침이 "최대한 빨리"다. ⓐ는 추가 공수 0일이다.
5. **되돌릴 수 있다.** §2.1 구조상 나중에 ⓑ로 바꿔도 **색 토큰 16개 + 대비표(0.5작업일)** 다. 지금 ⓐ로 진행하고 고객 반응을 본 뒤 바꾸는 것이 역순보다 싸다.

**동시에 권고하는 것**: PM이 고객에게 **ⓐ와 ⓑ를 나란히 보여주는 것**. 목업 3개가 이미 그 목적으로 만들어져 있고, ⓑ의 고객 설명 문장도 §5에 써 두었다. **고객이 ⓑ를 고르면 그때 바꾸면 된다** — 0.5작업일이다.

**권고하지 않는 조합**: ⓐ와 ⓑ의 색을 섞는 것(블루 + 세이지 동시 사용). 유채색이 2개가 되면 CTA의 유일성이 깨지고, 2차 배지 20종 이상에서 색 의미 체계가 무너진다.

### 7.1 ★ A단계(2~3일)만으로 어디까지 달라지는가 — designer 확인

개발팀이 권고한 분할(A 토큰·배경·모션 → B → C)에 맞춰 **A단계만으로 성립하는 구성**을 확인했다. 결론부터: **인상 변화의 대부분이 A단계에서 온다.**

| 진단 | A단계에서 해소되는가 | 이유 |
|---|---|---|
| **D-1 타이포가 작다** | **완전 해소** | display 74px·h1 52px·h2 40px·본문 17/16px·자간·행간은 **전부 토큰 값**이다. 마크업 변경 없이 토큰 교체만으로 적용된다 |
| **D-2 면이 흰색 하나뿐이다** | **완전 해소** | 면 4층(흰색/모래/스톤/딥) + 그라데이션 3종 + 노이즈는 **배경 선언**이다. 섹션에 클래스 한 줄씩 |
| **D-3 움직임이 0이다** | **대부분 해소** | M-1 스크롤 리빌 · M-3~M-6 hover는 **CSS 규칙 추가만**으로 끝난다. M-2 히어로 밑줄만 히어로 마크업에 `<span>` 1개가 필요하다 |
| **D-4 사진이 0장이다** | 해소 안 됨 | A·B·C 어느 단계로도 해소되지 않는다 — §4.3 |
| 남는 것(B·C 단계) | — | 히어로 아트 패널 재구성, 수업 유형 카드 상단 그래픽, 강사 카드·아바타 개편, 페이지 헤더 블록, 정적 키워드 스트립, 오시는 길 지도 자리·교통편 블록, 404 아트 |

> **designer 판단**: **A단계(2~3일) 완료 시점에 PM이 고객에게 보여드려도 된다.**
> 첫인상을 결정하는 세 요소(글자 크기·면의 층·움직임)가 A단계에 전부 들어 있다. B·C는 **완성도를 올리는 작업**이지 인상을 바꾸는 작업이 아니다.
> 다만 **SCR-001 히어로만은 A단계에 포함**해야 한다(아트 패널 + 밑줄 `<span>` 1개). 히어로가 v1.x 상태로 남으면 A단계의 효과가 절반으로 줄어든다.
