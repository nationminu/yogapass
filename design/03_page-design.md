### 2.2 Hero 상세 (스크롤 0 노출 보장)

화면정의서가 P3로 넘긴 3가지(최소 높이 · 크롭 세이프 영역 · 오버레이 불투명도)를 확정한다.

**① 360×640 단말에서 스크롤 0에 반드시 보여야 하는 3요소** = 헤드라인 · 서브카피 · 주 CTA

| 요소 | 높이 계산 |
|---|---|
| Hero 상단 패딩 | 32px |
| h1 27px × 1.3 × 2줄 | 70.2px |
| h1 하단 마진 | 12px |
| 서브카피 15px × 1.7 × 3줄 | 76.5px |
| 서브카피 하단 마진 | 20px |
| 주 CTA `primary lg` | 52px |
| **합계** | **262.7px** |

- 화면정의서가 계산한 가용 높이 **330~360px**(100dvh − 헤더 64 − 고정 바 60 − 브라우저 크롬) 안에 들어간다. **여유 67~97px.**
- eyebrow(32px + 8px 마진)와 보조 CTA(52px + 12px)·운영시간(24px)을 모두 넣으면 **390.7px**로 넘치므로, 화면정의서대로 **eyebrow·보조 CTA·운영시간은 첫 스크롤 구간으로 밀릴 수 있다**고 본다.
- **Hero 최소 높이 토큰**: `min-height: 320px`(`<768px`) / `420px`(`768~1279px`) / `520px`(`≥1280px`). `100dvh`를 쓰지 않는다 — iOS 주소창 변화로 CLS가 생긴다.

**② 사진 수령 시 규격** (현재는 CSS 라인 격자 그래픽)

| 항목 | 값 |
|---|---|
| 원본 | 16:9, 최소 1920×1080, AVIF/WebP, **200KB 이하** |
| 크롭 세이프 영역 | 이미지 **좌측 55% × 세로 중앙 70%** 에는 인물 얼굴·핵심 피사체를 두지 않는다(텍스트가 얹히는 자리) |
| 오버레이 | `<768px` `rgba(10,37,64,.78)` 균일 / `≥768px` `linear-gradient(90deg, rgba(10,37,64,.86), rgba(10,37,64,.68) 55%, rgba(10,37,64,.38))` |
| **불투명도 하한** | 텍스트가 놓이는 구간은 **0.68 미만 금지** (최악 조건 대비 5.50:1 — 디자인 시스템 §4.1 #26) |
| 텍스트 색 | 사진 사용 시 `#FFFFFF`로 전환. 사진이 없으면 현재대로 `#16263A` |
| 로딩 | `loading="eager"` `fetchpriority="high"` + `width`/`height` 지정(CLS 0) |
| 실패 시 | 대체 배경 `--color-navy` + 흰 텍스트(15.53:1) — 가독성 유지 |

### 2.5 개발 전달 노트

- h1은 이 화면에 1개(히어로). 섹션 제목은 전부 h2, 카드 제목은 h3.
- 히어로 그래픽 패널·강점 아이콘·위치 그래픽은 **전부 장식**(`aria-hidden="true"`) — 디자인 시스템 §4.3.
- 섹션 3·4는 **조건부 렌더**다. 서버 렌더 단계에서 데이터 유무를 판정하고, 빈 배열이면 섹션 태그 자체를 출력하지 않는다.
- 강점 카드 개수는 **3 또는 4**로 제한한다(REQ-F-011). 5개 이상이 들어오면 상위 4개만 렌더한다. 그리드는 `repeat(auto-fit, minmax(240px, 1fr))`가 아니라 **개수에 따른 명시적 열 수**를 쓴다(4개일 때 2×2가 되는 것을 막기 위함).
- 구조화 데이터(LocalBusiness)는 이 화면에 넣는다(REQ-N-012). 값 미확정 항목은 오픈 전 해소 대상.

| 본문 | "주소가 바뀌었거나 삭제된 페이지일 수 있습니다." | "잠시 후 다시 시도해 주세요. 급하신 경우 전화로 문의해 주세요." |
| 버튼 | "홈으로" + "문의하기" | "홈으로" (+ 전화 링크) |

**제약**: DB 장애 상태에서도 렌더되어야 하므로 **동적 데이터에 의존하지 않는다**. 전화번호·상호 등은 이 화면에서 **빌드 시점 상수 또는 정적 설정**으로 주입하고, 없으면 해당 블록을 뺀다. 스택 트레이스·내부 경로·버전을 화면에 출력하지 않는다.

## 10. 화면정의서와 다르게 설계한 곳 · 화면정의서가 P3로 넘긴 값

> **화면정의서와 충돌하는 설계는 없다.** 아래는 ⓐ 화면정의서가 명시적으로 P3에 위임한 값과 ⓑ 범위로 열려 있던 값을 단일 값으로 좁힌 것이다. 충돌이 아니라고 판단해 `to-planning` 티켓을 발행하지 않았다. **planner가 다르게 보면 리뷰로 지적해 주기 바란다.**
