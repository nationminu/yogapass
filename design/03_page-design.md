# 페이지 디자인 명세 v2.0 — 1차 (2026-11-06 오픈 범위)

> **범위**: 1차·공통 **6화면**(SCR-001·002·003·006·008·009). 2차 39화면은 이번 범위 밖이며 §9에 목록만 둔다.
> **v2.0(CR-002 디자인 고도화)이 바꾼 것은 시각 언어뿐이다.** 화면 수·섹션 구성·전환 동선·폼 항목·상태 규칙·예외 처리는 **v1.0 그대로**다. 무엇이 바뀌고 무엇이 그대로인지는 **§12 대조표**에 전건 정리했다.

> **전역 UI 규칙(G-0~G-13)의 단일 기준은 `planning/02_requirements.md` §3.0**이다. 이 문서는 화면별로 달라지는 것만 적는다.
> **모든 사실 정보(주소·전화·강사·요금·사업자 정보)는 `[TBD: 고객 확인 필요]`다.** 목업에도 실제 값처럼 보이는 문자열을 넣지 않았다.
> **개발팀 금지선(TKT-DEV-001 §A) 위반 0건.** 초안에서 마퀴·패럴랙스·`backdrop-filter`·`mix-blend-mode`·weight 300/800을 폐기했다.

### 2.2 Hero 상세 (스크롤 0 노출 보장)

**① 360×640 단말에서 스크롤 0에 반드시 보여야 하는 요소** = eyebrow · 헤드라인 · lead · 주 CTA

| 요소 | 높이 |
|---|---|
| Hero 상단 패딩 | 40px |
| eyebrow(26px) + 하단 마진 10px | 36px |
| display 34px × 1.12 × **2줄** | 76.2px |
| 헤드라인 하단 마진 | 18px |
| lead 16px × 1.75 × 2줄 | 56px |
| lead 하단 마진 | 28px |
| 주 CTA `btn-lg` | 58px |
| **합계** | **312.2px** |

- 가용 높이 **330~360px**(100dvh − 헤더 60 − 고정 바 62 − 브라우저 크롬) 안에 들어간다. **여유 17.8~47.8px.**
- **★ 콘텐츠 규칙: 모바일 헤드라인은 2줄 = 공백 포함 18자 이하로 쓴다.** 3줄이 되면 합계 350.3px로 여유가 사라진다. 이 규칙을 `planning/02_storyboard.md` SCR-001의 문안 작성 시 지켜야 한다(문안 확정 시 designer가 1회 확인).
- **Hero 최소 높이**: `min-height: 320px`(`<768px`) / `420px`(`768~1279px`) / `520px`(`≥1280px`). **`100dvh`를 쓰지 않는다** — iOS 주소창 변화로 CLS가 생긴다.
- 신뢰 지표 `<dl>`(운영시간·가까운 역·수업 유형)과 보조 CTA는 **첫 스크롤 구간으로 밀릴 수 있다.**

### 2.4 개발 전달 노트

- h1은 이 화면에 1개(히어로). 섹션 제목은 전부 h2, 카드 제목은 h3.
- 히어로 아트 패널·강점 아이콘·위치 그래픽·키워드 스트립 구분 점은 **전부 장식**(`aria-hidden="true"`).
- 섹션 4·5는 **조건부 렌더**. 빈 배열이면 섹션 태그 자체를 출력하지 않는다.
- 강점 카드 개수는 **3 또는 4**(REQ-F-011). 5개 이상이면 상위 4개만. 그리드는 `auto-fit`이 아니라 **개수에 따른 명시적 열 수**(4개일 때 2×2 방지).
- **난이도 표시는 점(장식, `aria-hidden`) + 글자 라벨**로 구성한다. 접근 이름은 글자 라벨이 담당한다.
- 구조화 데이터(LocalBusiness)는 이 화면에 넣는다(REQ-N-012).
- **전 화면 공통 스크립트 요건 2가지** (v1.0에서 변경 없음)
  1. **G-9 WebKit 폴백 스크립트에 `--fixed-bar-h`·`--header-h` 실측 갱신(`ResizeObserver`)을 함께 넣는다.**
  2. **바를 렌더하지 않는 구간(`≥1280px`, 400% 확대 조건)에서는 `removeProperty('--fixed-bar-h')`로 인라인 값을 되돌린다.**
- **skip link는 `<a class="skip" href="#main">본문 바로가기</a>` + `<main id="main" tabindex="-1">`.**
- **목업 HTML의 `style=` 속성은 목업 편의용이며 구현 명세가 아니다.** CSP가 인라인 스타일을 차단하므로 P4는 전부 클래스로 구현한다(TKT-DEV-001 A-8 · DEF-003 재발 방지).

## 11. 사진 촬영 지침 (PM이 고객에게 그대로 전달할 수 있게)

> **사진 5개소 전부 "사진이 들어와도 레이아웃이 바뀌지 않는다."** 현재는 같은 비율의 그래픽이 들어가 있고 교체만 하면 된다.
> **designer 우선순위: P-3 → P-1 → P-2.** P-3(강사)만 확보해도 체감 개선의 절반 이상이 온다 — 근거는 `03_design-concept.md` §4.3.

| ID | 위치 | 비율 | 최소 해상도 | 필요 장수 | 안전 영역 | 촬영 지침 |
|---|---|---|---|---|---|---|
| **P-1** | SCR-001 히어로 아트 패널 | **4:3** | **1600×1200** | 1 | 중앙 70% 안에 피사체. 좌하단 24%는 라벨이 덮을 수 있다 | **스튜디오 내부 전경.** 자연광, 사람은 실루엣이거나 2명 이하. 강한 원색 소품 배제(뮤트 팔레트와 충돌). **가로 촬영** |
| **P-2** | SCR-001 수업 유형 카드 상단 | **16:10** | **1200×750** | 수업 유형 수(3~5) | 중앙 80% | **동작 컷.** 같은 날·같은 조명에서 전부 촬영해 색온도를 맞춘다. 얼굴 식별이 필요 없으면 하반신·손 클로즈업도 좋다 |
| **P-3** ★ | SCR-001 강사 미리보기 · SCR-002 강사 카드 | **1:1** | **800×800** | 강사 수 | **얼굴이 상단 28% 지점**(`object-position: 50% 28%`) | **인물 상반신.** 배경은 단색 벽 또는 스튜디오. **전원 동일 배경·동일 프레이밍.** 초상권 동의 필수. 미제공 시 이니셜 카드 유지 — **인물 스톡 사진으로 대체하지 않는다** |
| **P-4** | SCR-003 오시는 길 상단 (선택) | **16:9** | **1920×1080** | 1 | 중앙 80% | **건물 외관 또는 입구.** 낮 시간, 간판이 읽히게. 처음 오는 사람이 찾는 데 쓰인다 |
| **P-5** | OG 이미지 배경 (선택) | **1200×630** | 1200×630 | 1 | 좌우 96px·상하 60px은 텍스트 영역 | P-1 재사용 가능. 단독 촬영 시 여백이 많은 구도로 |

**공통 촬영·납품 지침**

1. **가로 촬영** 기본(P-3 제외). 세로 원본은 크롭 손실이 크다.
2. **원본 그대로** 주십시오. 스마트폰 보정 필터·문자 삽입본은 쓸 수 없다. 압축·포맷 변환(AVIF/WebP)은 개발팀이 한다.
3. 최종 **1장당 200KB 이하**(P-3은 80KB 이하)로 압축한다. 원본은 크게 주셔도 된다.
4. **색감**: 따뜻한 자연광. 형광등 아래 차가운 색은 이번 팔레트(모래·크림)와 충돌한다.
5. **사람이 식별되는 사진은 초상권 동의서를 함께** 주십시오. 없으면 사용하지 않는다.
6. **스톡 사진을 쓸 경우**: 상업적 사용 + 웹 배포 허용 라이선스만. 출처·라이선스·취득일을 `design/assets/SOURCES.md` §4에 기록해야 한다. **인물 스톡으로 강사를 대체하는 것은 금지**(화면정의서 SCR-002 §3).
7. 사진 수령 시 **`design/assets/SOURCES.md` §4에 행을 추가한 뒤** 커밋한다.

**사진이 들어왔을 때 바뀌는 것 / 바뀌지 않는 것**

| 바뀌는 것 | 바뀌지 않는 것 |
|---|---|
| 그래픽 자리에 `<img>`가 들어간다 | 박스 비율·radius·그림자·주변 여백 |
| 총 전송량 (200KB × 장수 → **전송 예산 ≤280KB 재확인 필요**) | 섹션 순서·개수·CTA 위치 |
| `alt` 텍스트가 추가된다 | 대비 판정(사진 위에 텍스트를 얹지 않는 구조다) |

> ⚠ **사진 도입은 전송 예산(화면당 ≤280KB)에 직접 영향을 준다.** 현행 198KB + 히어로 사진 200KB = 398KB로 **예산을 넘는다.** 사진 수령 시 ① AVIF 우선 + `<picture>` 폴백 ② 히어로만 `eager`, 나머지 `loading="lazy"` ③ 반응형 `srcset`(모바일 800px 폭 이하 버전 별도) 를 반드시 적용해야 하며, **이 3가지를 적용한 뒤 developer가 재측정**한다. 사진 도입은 **별도 CR**로 처리한다(TKT-DEV-001 A-10).

**OG 이미지 재제작 필요** — 현재 `design/assets/og-image.svg`는 v1.x 팔레트(`#F0F5FB`·`#0B4F9E`·`#16263A`)로 만들어져 있다. **방향안 확정 후 v2.0 팔레트로 재제작**한다(0.25작업일). 확정 전에는 현재 파일을 그대로 쓴다 — 색이 조금 다를 뿐 오류는 아니다.
