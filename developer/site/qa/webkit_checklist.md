# WebKit(Safari · iOS) 실기기 검증 체크리스트 — 제작 제공본

> 기술 설계 §10.5 ③ 산출물. **검증 요건 ⑥(가상 키보드 검증 수단)** 의 제작 측 제공분이다.
> 기기 확보와 실제 수행은 qa·PM 소관이고, 제작은 ① 관측 신호 ② 자동화 판정 절차 ③ 이 체크리스트를 제공한다.
>
> ⚠ **데스크톱 브라우저의 뷰포트 축소로 대체하지 않는다** — 가상 키보드가 재현되지 않아 **거짓 Pass** 가 난다
> (페이지 디자인 §8.5 D-12). 자동화(②)는 "폴백 경로가 실행됐는가"만, 이 문서(③)는 "실제로 가려지는가"만 판정한다.

## 0. 준비

| 항목 | 값 |
|---|---|
| 대상 기기 | iOS Safari (iPhone, 360~430px 폭) · macOS Safari 최신 |
| 대상 URL | `/` · `/instructors` · `/location`(문의 폼) · `/privacy` · 존재하지 않는 경로(404) |
| 기록 | 각 항목마다 **기대 결과 · 실제 결과 · 캡처**(지정 지점) |
| 사전 확인 | 페이지 하단까지 스크롤해 레이아웃이 깨지지 않는지 1회 |

## 1. 관측 신호 (제작 구현분 — 자동화·수동 공통)

| 신호 | 확인 방법 | 의미 |
|---|---|---|
| `html[data-vk-fallback="1"]` | 요소 검사 또는 `document.documentElement.dataset.vkFallback` | `visualViewport` 폴백 경로가 **실제로 실행됐다** |
| `--fixed-bar-h` | `getComputedStyle(document.documentElement).getPropertyValue('--fixed-bar-h')` | 고정 바 실측 높이가 반영됐다 |
| `--body-pad-bottom` | 같은 방법 | 본문 하단 여백이 고정 바 높이를 따라간다 |
| `scroll-padding-bottom` | `getComputedStyle(document.documentElement).scrollPaddingBottom` | 앵커 이동 시 가려지지 않는다 |

## 2. 체크리스트

| # | 항목 | 절차 | 기대 결과 | 캡처 지점 | 결과 |
|---|---|---|---|---|---|
| ⓐ | **키보드 위에서 입력란·전송 버튼이 가려지지 않는가** | `/location#contact` → "문의 내용" 입력란 탭 → 키보드가 올라온 상태 | 입력 중인 필드와 **전송 버튼**이 키보드·고정 바에 가려지지 않는다 | 키보드 올라온 직후 전체 화면 | |
| ⓑ | **키보드를 닫으면 원복되는가** | 입력 완료 후 "완료"/화면 빈 곳 탭 | 레이아웃·스크롤 위치가 원래대로 돌아온다. 하단에 빈 공간이 남지 않는다 | 닫은 직후 | |
| ⓒ | **입력란 포커스 시 자동 확대(zoom)가 일어나지 않는가** | 이름·휴대폰·문의 내용 3개 필드를 차례로 탭 | **확대되지 않는다**(입력 글자 크기 16px 하한 — §9.1) | 포커스 직후 | |
| ⓓ | **주소 복사** | `/location` → "주소 복사" 버튼 | 복사되고 "복사했습니다" 안내가 뜬다. `http` 접근(보안 컨텍스트 아님)에서는 `execCommand` 폴백으로 동작한다 | 안내 표시 시점 | |
| ⓔ | **모바일 메뉴(CMP-005) 개폐와 포커스 순서** | 헤더 메뉴 버튼 탭 → 열기 → Tab/VoiceOver 이동 → 닫기 | 열림·닫힘이 동작하고 포커스가 메뉴 밖으로 새지 않으며 닫으면 메뉴 버튼으로 돌아온다 | 열린 상태 | |
| ⓕ | **Safari 하단 툴바와 겹치는 구간** | 페이지를 아래로 스크롤해 툴바가 축소/확장되는 순간 관찰 | 고정 바·본문이 `env(safe-area-inset-bottom)` 만큼 띄워져 툴바에 가려지지 않는다 | 툴바 확장 순간 | |
| ⓖ | **가로 모드(landscape)** | 기기를 가로로 회전 후 ⓐ 반복 | 가려짐 없음. 가로 스크롤 0 | 회전 직후 | |
| ⓗ | **폼 제출 결과 블록 포커스** | 문의 제출(성공/오류 각 1회) | 결과 블록으로 포커스가 이동하고 VoiceOver 가 읽는다 | 결과 표시 시점 | |
| ⓘ | **시간이 지난 폼 재제출(⑦)** | 폼을 연 채 24시간 이상 두었다가 제출(또는 검증에서 `submit_token` 을 비워 제출) | "시간이 지나 문의가 접수되지 않았습니다" 안내가 뜨고 **입력값이 남아 있으며** 다시 제출하면 접수된다 | 안내 표시 시점 | |

## 3. 판정

- ⓐ·ⓑ·ⓕ 중 하나라도 실패하면 **G-9(가상 키보드 대응) 결함**으로 본다.
- ⓒ 실패는 입력 글자 크기 회귀(16px 하한 위반) 신호다.
- 자동화(②)가 Pass 인데 ⓐ 가 Fail 이면 **폴백은 실행됐지만 값이 틀린 것**이므로 `--fixed-bar-h` 실측값을 함께 기록한다.
