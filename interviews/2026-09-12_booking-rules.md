# 예약 규칙 — 월별 스케줄 편성·게시, 캘린더 예약, 상담 예약

> **출처**: 2026-09-12 총괄 PM 지시 (누적)
> 1. 예약은 레슨 기준, 06:00~20:00(조절 가능), 점심시간 제외. 예약 가능 여부는 캘린더로 표시하고 가능할 때만 예약된다.
> 2. 레슨 길이는 **60분**.
> 3. 슬롯은 관리자가 유연하게 열고 닫는다.
> 4. 관리자가 **월별 스케줄을 편성해 게시**하고 그 캘린더로 예약을 받는다. "예약 후 강사 배정"은 취소. **월별 템플릿**을 제공한다.
> 5. **게시는 전월에 관리자가 직접 한다(매월 1일 전). 일정 등록 시 강사 배정은 필수. 공휴일도 운영하며 관리자가 템플릿 기반으로 게시 전 수정한다. 강사 관리 기능을 포함하되, 초기에는 강사 정보 관리 수준으로 하고 강사 기간(근무·휴무) 관리는 다음 단계로 미룬다.**
> 6. **체험 후 상담·신규 등록 상담·임산부 상담 등 방문 상담은 캘린더 예약과 별개로, 희망 일자·시간을 받는 별도 창구를 만든다.**
> 7. **상담 예약은 비회원도 신청할 수 있다. 레슨 캘린더와 연계하지 않는다. 건강 정보(임신 주수 등)는 받지 않는다. 신청 항목은 일자·시간·이름·연락처이며 회원이면 자동 기입한다. 접수 후 해피콜로 확정한다.**
>
> 이 문서는 [ITV-001](2026-09-12_customer-interview.md)의 "시간표에서 수업 선택"과 v0.1의 "신청 → 관리자 강사 배정 → 확정" 흐름을 **대체**한다. 정식 요구사항은 CR-001 승인 후 `planning/02_requirements.md`에 반영한다.

# A. 레슨 예약 (캘린더)

## 1. 예약 단위

| 항목 | 값 | 조절 |
|---|---|---|
| 레슨 길이 | **유형별 60분 또는 90분** (B-4 확정) | 유형 설정에서 변경 |
| 슬롯 시작 시각 | **30분 단위 그리드** (06:00, 06:30, 07:00 …) | — |
| 슬롯 간 휴식 | 없음 (연속 배치 가능) | 관리자 설정 (0·10·15분) |
| 운영 시간 | **06:00 ~ 20:00, 주말 포함 기본 운영** (B-2 확정) | 관리자 설정, 요일별 |
| 점심시간 | **11:00 ~ 13:00은 기본 닫힘.** 차단 구간이 아니라 기본값이며, 관리자가 필요하면 이 시간대에도 슬롯을 연다 (B-1 확정) | 관리자 설정 |

## 1-1. 레슨 유형 (B-4 확정)

슬롯마다 유형을 지정하고, 유형이 길이·정원의 기본값을 결정한다. 유형 목록은 관리자가 추가·수정한다.

| 유형 | 설명 | 기본 길이 | 기본 정원 |
|---|---|---|---|
| 그룹 요가 | 하타·빈야사 등 매트 기반 단체 수업 | 60분 | `[TBD]` (인터뷰 기준 8명) |
| 키즈 요가 | 아동·청소년 대상 (체형 교정·집중력) | 60분 | `[TBD]` |
| 플라잉 요가 | 천장 해먹을 쓰는 공중 요가 | 60분 | 해먹 수만큼 `[TBD]` |
| 로우 플라잉 | 해먹을 낮게 걸어 진행하는 플라잉 (초보·재활 성향) | 60분 | 해먹 수만큼 `[TBD]` |
| 리포머 | 리포머 기구를 쓰는 수업 | 60~90분 | 기구 수만큼 `[TBD]` |

- **개인 레슨(1:1)은 캘린더 예약 대상이 아니다.** 상담 창구에서 접수해 일정을 조율한다 (B-4 확정, §6 상담 유형 참조).
- 길이·정원 기본값과 실제 운영 유형은 고객 확인이 필요하다 (B-16).
- 유형별 장비(해먹·리포머) 수가 정원 상한이 되므로 설비 수량 확인이 필요하다 (B-16).

## 2. 후보 슬롯 생성 규칙

유형마다 길이가 다르므로 고정된 슬롯 표를 미리 만들지 않는다. **관리자가 편성 화면에서 슬롯을 배치한다.**

1. 편성 화면은 운영 시간(06:00~20:00)을 **30분 단위 그리드**로 보여준다.
2. 슬롯을 추가할 때 **시작 시각 + 유형 + 강사 + 정원**을 지정하면, 유형의 기본 길이(60·90분)로 종료 시각이 자동 계산된다.
3. 운영 종료 시각을 넘기는 슬롯은 만들 수 없다.
4. **겹침 검사** — 같은 시간대에 슬롯이 겹치면 경고한다. 같은 강사가 겹치는 것은 막는다. 공간이 하나뿐이면 슬롯 자체가 겹칠 수 없다 (공간 수 확인 필요 — B-15).
5. **11:00~13:00은 기본적으로 비워 두되**, 관리자가 슬롯을 배치하면 그 시간에도 수업이 열린다.

**예시** (06:00~20:00, 60분 수업 기준) → 하루 최대 13슬롯을 배치할 수 있다. 실제로 몇 개를 열지는 §3 월별 편성에서 정한다.

## 3. 월별 스케줄 편성과 게시

### 3.1 흐름

```
① 월 템플릿 불러오기  →  ② 월 스케줄 편집  →  ③ 검토  →  ④ 게시(전월, 수동)  →  ⑤ 회원 예약
   (주간 반복 패턴)       슬롯 개폐                미리보기    매월 1일 전            즉시 확정
                          강사 배정(필수)          미배정 검사
                          정원 지정
                          공휴일 조정
```

### 3.2 게시 규칙 (B-11 확정)

- **다음 달 스케줄은 전월에 게시한다. 매월 1일 전까지 게시 완료.**
- **자동 게시하지 않는다.** 관리자가 내용을 확인하고 직접 게시한다.
- 게시되지 않은 달은 회원에게 "준비 중"으로 보이고 예약할 수 없다.
- 게시 기한이 다가오면 관리자에게 알린다 (예: 매월 25일 미게시 시 알림) — 알림 방식은 P4에서 정한다.

| 상태 | 의미 | 회원에게 |
|---|---|---|
| 작성 중 | 편성 중, 비공개 | "준비 중", 예약 불가 |
| 게시됨 | 공개, 예약 접수 중 | 캘린더·슬롯 노출 |
| 마감 | 지난 달 또는 접수 종료 | 열람만 가능 |

### 3.3 강사 배정 (B-12 확정)

- **슬롯을 열 때 강사 배정은 필수다.** 강사가 없는 슬롯은 만들 수 없다.
- 게시 전 검사에서 미배정 슬롯이 하나라도 있으면 **게시를 막고** 해당 슬롯을 표시한다.
- 한 강사는 같은 시간대의 두 슬롯에 배정될 수 없다.

### 3.4 월별 템플릿 (B-13 확정)

- 템플릿은 **요일 × 시간 × 강사 × 정원**의 주간 반복 패턴이다.
- 이름을 붙여 여러 개 저장한다 (예: "평일 기본", "여름 단축 운영").
- **공휴일도 정상 운영한다.** 시스템이 공휴일을 자동으로 빼지 않으며, **관리자가 템플릿을 적용한 뒤 게시 전에 직접 수정**한다(공휴일 특별 운영·휴무·강사 교체 등).
- → 공휴일 데이터 연동이 필요 없다. 개발 범위가 줄어든다.
- 편성한 월 스케줄을 **새 템플릿으로 저장**할 수 있다.

### 3.5 게시 후 변경

| 상황 | 처리 |
|---|---|
| 예약자가 없는 슬롯 | 자유롭게 열고 닫고 강사 변경 |
| 예약자가 있는 슬롯의 강사 변경 | 변경 후 예약자에게 변경 안내 이메일 |
| 예약자가 있는 슬롯 닫기 | 바로 닫지 않는다. 예약자 수 확인 후 취소 처리 + 취소 안내 이메일 |
| 지난 슬롯 | 변경 불가 (이력 보존) |

## 4. 캘린더 표시 (회원)

- 예약 페이지는 **게시된 월의 캘린더**를 보여준다.

| 상태 | 표시 | 선택 |
|---|---|---|
| 예약 가능 | 잔여 슬롯 수 또는 "예약 가능" | 가능 |
| 마감 | "마감" | 불가 |
| 휴무 | "휴무" | 불가 |
| 미게시 월 | "준비 중" | 불가 |

- 날짜를 고르면 슬롯 목록이 열리고, 슬롯마다 **시간·담당 강사·잔여 인원**을 보여준다.
- 하루에 슬롯이 많을 수 있으므로(최대 13개 수준) **오전·오후로 나누어** 표시한다(모바일 대응).
- 슬롯에는 **유형(그룹·키즈·플라잉·로우 플라잉·리포머)** 을 함께 표시한다.
- 예약 가능한 슬롯만 선택된다. 색상만으로 상태를 구분하지 않는다(접근성).

## 5. 예약 성립 조건

모두 충족하면 **즉시 확정**된다. 별도 승인 단계는 없다.

1. 로그인한 회원이다 (비회원 불가)
2. 해당 월 스케줄이 **게시** 상태다
3. 슬롯이 열려 있다 (강사는 이미 배정되어 있다)
4. 슬롯 정원에 여유가 있다
5. 최소 리드타임이 남아 있다 — `[TBD]` (B-5)
6. 1인당 동시 예약 한도를 넘지 않는다 — `[TBD]` (B-5)

> **동시 예약 처리**: 마지막 한 자리를 두 사람이 동시에 누르면 한 명만 성공해야 한다(P4 기술 설계 항목).

**예약번호** (C-10 확정): 레슨 예약이 확정되면 **예약번호**를 발급한다. 상담 신청번호와 같은 방식(추측 불가한 무작위 값)이며, 마이페이지 목록과 확정 안내 메일에 표시한다. 회원 전용이므로 번호로 조회하는 창구는 두지 않고, 전화 응대·문의 확인용으로 쓴다.

**취소**: 회원은 수업 시작 3시간 전까지 마이페이지에서 직접 취소한다. 취소한 자리는 다시 예약 가능해진다.

# B. 상담 예약 (캘린더 외 별도 창구)

> **PM 지시**: 체험 후 상담, 신규 등록 상담, 임산부 상담 등 방문 상담은 캘린더 예약과 별개로 **희망 일자·시간을 받는 별도 창구**로 처리한다.

## 6. 상담 유형

| 유형 | 설명 |
|---|---|
| 체험 후 상담 | 체험 수업을 받은 뒤 등록 상담 |
| 신규 등록 상담 | 처음 방문해 수강 상담 |
| 임산부 상담 | 임신 주수·건강 상태를 고려한 프로그램 상담 |
| **개인 레슨(1:1) 상담** | 1:1 수업 희망 — 일정·요금을 상담으로 조율 (B-4 확정) |
| 기타 방문 상담 | 위에 없는 방문 문의 |

유형 목록은 관리자가 추가·수정할 수 있다.

## 7. 신청 방식

- **캘린더를 쓰지 않는다.** 슬롯·정원과 무관하게 **희망 일자와 시간을 직접 입력**받는다 (C-2 확정: 레슨 캘린더와 연계하지 않는다).
- **비회원도 신청할 수 있다** (C-1 확정). 로그인한 회원이면 **이름·연락처가 자동으로 채워진다.**

| 입력 항목 | 필수 | 비고 |
|---|---|---|
| 상담 유형 | 필수 | 목록에서 선택 |
| 희망 일자 | 필수 | **내일 이후만 선택 가능(당일 불가). 먼 미래 제한은 없다** — C-8 확정 |
| 희망 시간 | 필수 | 시간 선택 (운영 시간 안내) |
| 이름 | 필수 | 회원은 자동 기입 |
| 연락처 | 필수 | 회원은 자동 기입 |
| 남길 말 | 선택 | |
| 개인정보 수집·이용 동의 | 필수 | 비회원 신청 시 |

**신청번호 발급** — 접수되면 **신청번호**를 발급한다. 비회원은 이 번호로 신청을 조회·취소한다.
- 형식: 추측할 수 없는 무작위 값 (예: `YP-A7KD-M2XF`). 순번처럼 남의 번호를 유추할 수 있는 방식은 쓰지 않는다.
- 전달: 접수 완료 화면에 크게 표시하고 "번호를 저장해 주세요"라고 안내한다. 이메일 주소가 있는 회원 신청에는 메일로도 보낸다.
- 회원은 마이페이지에서 번호와 상태를 다시 볼 수 있으므로 번호를 따로 보관하지 않아도 된다.
- 번호를 잃어버린 비회원은 전화로 확인한다.

- **건강 정보(임신 주수 등)는 받지 않는다** (C-3 확정). 임산부 상담도 유형 선택만 하고, 상세한 내용은 해피콜에서 구두로 확인한다. → 민감정보를 저장하지 않으므로 개인정보 처리 부담이 줄어든다.

### 중복 신청 처리 (C-6 확정)

| 상황 | 처리 |
|---|---|
| **일자 + 시간 + 연락처가 모두 같은** 신청 | **차단.** "같은 일시로 이미 신청하셨습니다"를 표시하고 접수하지 않는다 |
| 연락처는 같고 **일시가 다른** 신청 | **차단하지 않는다.** 기존 신청이 있다고 안내한 뒤 그대로 접수한다 |
| 취소·완료된 과거 신청 | 중복으로 보지 않는다 |

> ⚠️ **안내 문구의 개인정보 주의**: 연락처만 입력하면 누구나 그 번호의 신청 내역을 볼 수 있으므로, 안내에 일자·시간을 그대로 노출하면 타인의 정보가 새어 나갈 수 있다.
> **안내 문구 (PM 확정)** — **"이 연락처로 접수된 신청이 있습니다. 예약 확인 또는 전화로 문의주세요."**
> 일자·시간·유형 등 신청 상세는 표시하지 않는다. 로그인한 회원에게는 본인 신청이 확인되므로 마이페이지에서 상세를 볼 수 있다.
> 이 문구가 안내하는 "예약 확인" 경로는 회원은 마이페이지, 비회원은 §8-1 조회 창구다 (C-7 확정).

## 8-1. 상담 신청 확인 (비회원 조회 창구) — C-7 확정

비회원도 자신의 상담 신청을 확인할 수 있어야 한다. 로그인 없이 쓰는 조회 창구를 둔다.

| 항목 | 내용 |
|---|---|
| 확인 수단 | **신청번호 + 연락처가 일치**할 때 조회된다 |
| 표시 항목 | 상담 유형, 희망 일시, 상태(접수·확정·완료·취소), 확정 일시 |
| 표시하지 않는 것 | 남길 말, 관리자 메모, 해피콜 기록 |
| **취소** | **조회 화면에서 바로 취소할 수 있다** (신청번호 + 연락처로 본인 확인됨 — C-9 확정). 취소하면 관리자에게 알림 메일이 간다 |
| 취소 가능 시점 | 상담 예정 일시 **전까지**. 완료·이미 취소된 건은 불가 |
| 회원 | 마이페이지에서 같은 내용을 본다. 조회 창구를 쓸 필요가 없다 |

**보안 규칙** (번호+연락처 2가지가 맞아야 하며, 아래 보완을 함께 둔다)
- 조회·취소 시도에 **빈도 제한**을 둔다 (기준값: 10분 10회, 초과 시 10분 차단) — 번호를 무작위로 넣어 보는 시도를 막는다
- 일치하는 신청이 없을 때와 조회에 실패했을 때 **같은 문구·같은 응답 시간**으로 응답한다 (번호 존재 여부를 알아내지 못하게)
- 연락처는 화면에 **마스킹**해서 보여준다 (예: 010-****-1234)
- 취소·완료된 신청은 일정 기간 후 조회 대상에서 제외한다 (기간은 개인정보 보관 정책에 따름)

> 화면은 별도 페이지로 둘지, 상담 예약 페이지 안의 탭으로 둘지 기획 단계에서 정한다.

## 8. 처리 흐름

```
회원/비회원 신청 → [접수] → 관리자 해피콜(전화 확인·일정 조율) → [확정] → 방문 상담 → [완료]
      │  (신청번호 발급)                  └─ 일정 불가·미응답 → [취소]
      └─ 신청자 취소 (신청번호 + 연락처 / 회원은 마이페이지) → [취소]
```

| 상태 | 의미 |
|---|---|
| 접수 | 신청 도착, 해피콜 전 |
| 확정 | 해피콜로 일정 합의 완료 (관리자가 확정 일시 입력) |
| 완료 | 상담 진행됨 |
| 취소 | 신청자 취소 또는 일정 불발 |

- 신청 즉시 **신규 상담 알림 이메일**이 관리자에게 간다.
- 신청자에게는 **화면으로 접수 완료를 안내**한다("담당자가 연락드립니다"). 이메일 주소가 있는 회원 신청에는 접수·확정 안내 메일도 보낸다. 비회원은 연락처만 받으므로 메일을 보내지 않는다.
- 관리자는 상담 신청 목록에서 **해피콜 결과**(통화 여부·확정 일시·메모)를 기록하고 상태를 바꾼다.
- **해피콜 미응답 시 처리 규칙은 시스템에 두지 않는다** (C-5 확정). 재시도·취소 판단은 상담 담당자가 하고, 결과만 상태로 남긴다. 자동 취소·자동 재알림 기능은 만들지 않는다.
- 상담 신청은 레슨 예약 정원·슬롯에 영향을 주지 않고, **레슨 캘린더에도 표시하지 않는다**(C-2 확정). 관리자 화면의 상담 목록에서만 관리한다.
