# 인터뷰 결과 요약과 진행 방안 (초안)

> **성격**: 가상 인터뷰([ITV-001](2026-09-12_customer-interview.md)) 기반의 **오케스트레이터 초안**이다. 정식 영향도 분석·권고는 CR-001 절차에서 pmo가 수행하고, 결정은 PM이 한다.
> 공수·일정 수치는 P1·P2 리뷰에서 developer가 낸 추정(±30%)을 바탕으로 한 **1차 환산치**이며, developer 검토 전이다.

## 1. 인터뷰로 결정된 것

| 쟁점 | 결과 |
|---|---|
| 예약 방식 (ADR-001 ①) | **즉시 확정형 = B안(자체 예약 시스템)** — 회원이 시간표에서 수업 선택 → 정원 안에서 바로 확정 |
| 예약 자격 | **회원가입 필수.** 비회원은 시간표 열람과 일반 문의만 |
| 예약 조회 (ADR-001 ②) | 마이페이지에서 본인 예약 목록·취소(수업 3시간 전까지)·이력 |
| 상태 변경 수단 | **관리자 화면** (계정 2개) — 예약 확인·취소, 시간표 등록, 공지, 회원 목록 |
| 예약번호 (ADR-001 ③) | **불필요** — 로그인 기반 조회로 대체. 기존 예약번호 요구(REQ-F-R-006 등) 폐기 |
| 알림 | 예약 확정·취소 이메일. 문자·알림톡 제외 |
| 결제·수강권 차감 | **범위 밖** (현장 결제·계좌이체) |
| 오픈일 | 10월 말 희망하지만 **기능 우선**. 단계 오픈 수용, 늦어도 11월 중순 전체 오픈 희망 |
| 직접 수정 | 시간표·공지는 고객이 직접 (관리자 화면) |
| 예산 | 외부 서비스 월 5만 원 이내, 계정은 고객 명의 |

## 4. 진행 방안 3가지

### 방안 1 — 단계 오픈 (권고)

| 차수 | 범위 | 오픈 예정 |
|---|---|---|
| 1차 | 소개형 사이트: 메인·강사 소개·오시는 길·개인정보 처리방침·일반 문의 폼, 운영 시간·수업 안내 **정적 노출** | **10월 27~30일** (계획 기준선 유지) |
| 2차 | 회원가입·로그인·마이페이지·**캘린더 슬롯 예약**(즉시 확정)·관리자 화면(설정·휴무일 포함)·이메일 알림 | **11월 27일 ~ 12월 9일** |

- **장점**: 고객이 수용한 방식이고, 10월 말에 사이트가 실제로 열려 홍보·검색 노출을 먼저 시작할 수 있다. 1차에서 디자인·인프라를 확정해 2차 위험이 줄어든다.
- **단점**: 게이트가 두 번 돌아 관리 부담이 늘고, 1차 시간표를 정적으로 넣었다가 2차에서 관리자 입력으로 바꾸는 **전환 작업(0.5~1일)** 이 생긴다.
- 기획 문서는 1차/2차를 **하나의 문서에서 차수 표시**로 관리하면 재작성이 아니라 표시 추가로 끝난다.

### 방안 2 — 전체 일괄 오픈
- 오픈 **11월 24일 ~ 12월 4일**. 전환 작업이 없고 관리가 단순하다.
- 고객 희망(11월 중순)을 1~2주 넘기고, 10월 말까지 보여줄 결과물이 없다.

### 방안 3 — 기능 축소 후 일괄 오픈
- 관리자 화면을 빼고(예약 확인은 이메일·스프레드시트), 즉시 확정 대신 **신청 → 관리자 확정** 방식으로 축소.
- 오픈 **11월 6~13일**로 앞당겨지지만, 고객이 인터뷰에서 밝힌 두 가지 목적(전화 응대 감소, 시간표 직접 수정)을 충족하지 못한다. **권고하지 않는다.**

## 5. 기술 방향 (P4에서 확정)

- 회원·예약·관리자 기능이 생기면서 **정적 사이트로는 불가능**하다. 서버·데이터베이스·인증이 필요하다.
- 후보: 웹 프레임워크(SSR) + 관리형 Postgres·인증 서비스. **서울 리전**을 제공하는 서비스를 우선한다(개인정보 국외 이전 고지 회피).
- ⚠️ **Vercel Hobby(무료) 요금제는 상업적 사용이 금지**된다(developer P1 리뷰 확인). 상업 사이트이므로 유료 요금제나 상업 사용이 허용되는 무료 서비스를 써야 한다. 고객 예산(월 5만 원)으로 가능한 조합을 P4 기술 설계에서 비교한다.
- 비밀번호 저장, 세션 관리, 권한 분리(회원/관리자), 접근 로그가 새로 필요하다 → 보안 요구사항이 늘어난다.
