# 정보구조 (IA) — 강남 요가패스 홈페이지

> **읽는 법 (검토자·PM용)**
> 1. **v0.5는 CR-001(회원제 예약 시스템 도입) 승인에 따른 개정본이다.** 화면이 8개에서 **45개**로 늘었고, 사이트가 **공개 / 회원 전용 / 관리자 전용** 3영역으로 나뉘었다. v0.4의 "메뉴 페이지 6종 고정"과 "예약 영역 ADR-001 대기(§7 차이표)"는 **모두 폐기**됐다(요구사항 §4.5).
> 2. **화면 번호·이름·차수의 기준선은 `02_requirements.md` §9**다. 이 문서는 그 값을 그대로 옮기며 자체 목록을 유지하지 않는다. 불일치가 생기면 **§9가 맞고 이 문서를 고친다.**
> 3. **하단 고정 바·고정 헤더의 단일 기준은 `02_requirements.md` §3.0(G-0~G-13)** 이다. 이 문서는 §5.1에서 **참조만** 하고 값을 복제하지 않는다(v0.4와 같은 원칙, 항목만 G-11 → G-13으로 확장).
> 4. **모든 화면·메뉴·흐름에 `차수`(1차 / 2차 / 공통)를 표시한다.** 1차(2026-11-06 오픈)는 **소개형 + 일반 문의 폼**이고, 2차(2027-01-22 오픈)에서 회원·레슨 예약·상담 예약·관리자가 붙는다.
> 5. **v0.5 주요 결정 4건** — ① **2차 GNB를 주 메뉴 5개 + 유틸(회원) 영역으로 재설계**(§2.1) ② **URL 규칙 신설**(`/consult`·`/booking`·`/mypage`·`/admin` 계열, **연번 ID 금지** — §6.1) ③ **색인 정책을 영역 기준으로 재작성**(공개만 색인, 회원·관리자 `noindex` + robots Disallow 금지 — §6.5) ④ **description은 색인 대상 공개 7화면만, title은 전 45화면**(§6.2·§6.3).
> 6. 사실 정보(주소·전화·강사·요금·사업자 정보 등)는 모두 `[TBD: 고객 확인 필요]`다. 항목은 요구사항 §8.1 T-A~T-H.

### 1.4 구조 판단 근거

| 판단 | 내용 |
|---|---|
| **1depth 유지(공개 영역)** | 공개 영역은 여전히 평면 구조다. `/consult/*`·`/signup/complete`·`/password/reset/confirm`은 **메뉴에 노출하지 않는 후속 화면**이라 2depth로 보이지 않는다. 모바일에서 2depth 메뉴는 조작 부담만 늘린다 |
| **`/booking`·`/mypage` 분리** | 예약 "행위"(`/booking`)와 예약 "내역"(`/mypage/bookings`)을 같은 경로에 묶지 않는다. 진입 목적이 다르고(예약하러 / 확인하러) 고정 바 CTA의 자기 참조 판정(§3.0 G-6)도 URL 접두어로 단순해진다 |
| **상담 = 공개 / 레슨 = 회원** | 상담은 비회원도 신청·조회하므로 공개 영역(`SCR-005·020·021`), 레슨 예약은 회원 전용이므로 회원 영역(`SCR-110~113`)이다(booking-rules §5-1·§7) |
| **관리자 별도 셸** | 관리자는 전환(예약·전화)이 목표가 아니라 편성·처리가 목표다. 공개 헤더·GNB·고정 바를 쓰지 않고 사이드바 셸을 쓴다(§3.0 G-13, REQ-F-A-002) |
| **폐기된 전제** | 계획서 v1.0 §2.1 "페이지 추가 원칙(메뉴 5종 한정)"과 v0.4 §7 "예약 영역 IA 차이표(A/A'-1/A'-2a/A'-2b/C)"는 CR-001로 폐기됐다. `SCR-004`(예약 신청)·`SCR-007`(예약 신청 완료)은 **번호를 재사용하지 않는다** |

> ⚠ **계획서 v2.0 §2.1(1)과의 차이 1건** — 계획서는 1차 공개 페이지에 "**예약 안내**(2차 오픈 예정 안내 + 문의 폼·전화 유도)"를 별도 페이지로 적었으나, 요구사항 §9.2의 1차 화면 목록에는 그런 화면이 없다. **이 문서는 §9를 따르고, 1차 "예약 안내"는 별도 화면이 아니라 ⓐ 메인 수업 안내 섹션의 안내 문구(REQ-F-014)와 ⓑ 오시는 길 문의 폼 진입 문구로 처리한다.** 별도 화면이 필요하면 pmo가 계획서를 정정하거나 CR로 SCR을 추가해야 한다(§8 확인 필요 #1).
> **📌 PM 결정 대기 (v0.6 표기)** — 이 불일치는 **PM 결정 대기 상태**이며, 결정 전까지 기획 3문서는 **현행(별도 화면 없음)을 유지**한다. 결정이 "별도 화면 필요"로 나오면 SCR 신규 발행 → 요구사항 §9.2 · IA §1·§3.1·§6.2·§6.3 · 화면정의서를 함께 개정한다(영향 범위: SCR 1개 추가, title·description 1행씩, 사이트맵 1줄, 1차 화면 수 6 → 7).

**뷰포트별 헤더 구성 (v0.5 확정 · v0.6 구간 표기 전환)**

> **이 표가 헤더 구성의 단일 값이다.** 요구사항 §3.0 G-12는 이 표를 참조만 하고 값을 복제하지 않는다(v0.6 — designer R1 #4 ②).
> **뷰포트는 점값이 아니라 구간으로 규정한다**(요구사항 §3.0 G-1). 360·768·1280px는 **측정 지점**이며, 그 사이 폭(예: 1024px)은 해당 구간 규칙을 따른다.

| 뷰포트 구간 | 1차 | 2차 |
|---|---|---|
| **`<768px`** (측정 지점 360px) | 로고 + **햄버거** + 전화 아이콘. GNB 4개는 패널 안 | 로고 + **햄버거** + 전화 아이콘. 패널 안에 **주 메뉴 5 + 회원 메뉴 섹션**(로그인·회원가입 / 마이페이지·로그아웃) |
| **`768~1279px`** (측정 지점 768px · **1024px도 이 구간**) | 로고 + **인라인 GNB 4개** + 전화 아이콘. 햄버거 없음, **헤더 CTA 없음**(§3.0 G-8) | 로고 + **인라인 GNB 5개** + 전화 아이콘 + **회원 유틸 슬롯**. 햄버거 없음, 헤더 CTA 없음<br>**유틸 슬롯은 로그인 상태로 나뉜다 (v0.6 — designer R1 #3)**<br>· **비로그인**: **"로그인" 텍스트 버튼**(약 56px). "회원가입"은 로그인 화면 안에서 잇는다<br>· **로그인**: **사람 아이콘 1개(44×44px) + 드롭다운**(마이페이지·내 레슨 예약·내 상담 신청·로그아웃) |
| **`≥1280px`** (측정 지점 1280px) | 로고 + 인라인 GNB 4개 + **주 CTA 강조 버튼("문의하기")** + 전화번호 텍스트 | 로고 + 인라인 GNB 5개 + **주 CTA 강조 버튼**(비로그인 "상담 예약" / 로그인 "레슨 예약") + **회원 유틸 텍스트**(로그인 / 마이페이지·로그아웃) + 전화번호 텍스트 |

> **`768~1279px` 구간 GNB 폭 계산 (v0.6 — designer R1 #2로 전제·폴백을 명시)**
> **전제 3개 (v0.7 — designer R2 #N2로 ②를 조임)** — ① **로고 폭 ≤ 140px** ② **GNB 항목 좌우 패딩 ≤ 12px**(v0.6의 "≤ 16px"에서 축소) ③ **본문 16px**. 세 전제가 모두 성립할 때만 아래 결론이 유효하다.
> **계산 (v0.7 정정)**: 768 − 로고 140 − 전화 아이콘 44 − 유틸 슬롯 **44~56**(로그인 아이콘 44 / **비로그인 "로그인" 텍스트 버튼 56**) − 좌우 여백 약 40 = GNB 가용 **약 488~500px**. 2차 주 메뉴 5개는 항목 패딩 12px 기준 `44+92+92+92+92 = 412 + 간격 4×8 = **444px**` → **가용 폭 안이라 축약 없이 들어간다**(최악 조합 = 비로그인 유틸 56px + 패딩 12px에서 **여유 44px**).
> ⚠ **패딩 16px으로 넓히면 항목 5개가 각각 +8px씩 늘어 `52+100×4 = 452 + 간격 32 = 484px`이 되고, 최악 여유가 4px밖에 남지 않는다**(글리프 폭이 넓은 폰트를 쓰면 로고를 받기도 전에 폴백 ②가 발동한다). 따라서 **전제 ②를 12px로 고정**한다 — P3는 이 값을 토큰으로 확정한다.
> ⚠ **전제 ①은 아직 확보되지 않은 자산에 걸려 있다** — 로고는 `[TBD — T-B]`이며 **가로형 워드마크가 오면 180px을 넘어 결론이 뒤집힐 수 있다.**
> **폴백 순서 (로고 수령 후 IA를 고치지 않고 P3에서 흡수한다)**: ① `768~1279px` 구간에서 로고를 **심볼 전용(44px)** 으로 전환 → ② GNB 항목 좌우 패딩을 **8px**로 축소 → ③ **"레슨 예약"을 유틸 드롭다운으로 이동**. 위에서부터 순서대로 적용하고, ③까지 써야 하면 designer가 티켓으로 알린다.
> **유틸을 아이콘으로 두는 이유(로그인 상태 한정)**: "마이페이지"·"로그아웃" 두 텍스트(약 140px)를 그대로 펼치면 GNB 가용 폭이 부족해 메뉴가 줄바꿈된다. **사람 아이콘 1개 + 드롭다운**이면 폭이 44px로 고정된다. **비로그인 상태는 유틸 항목이 "로그인" 하나뿐이라 그 문제가 없고**, 아이콘 단독은 비회원에게 "마이페이지"로 읽혀 **1차 전환 동선(로그인·회원가입)이 드롭다운 한 단계 뒤로 숨는다.** 상태 간 폭 차이가 12px뿐이라 "레이아웃이 로그인 상태에 따라 흔들리지 않는다"는 취지는 유지된다. 드롭다운의 접근 이름·`aria-expanded`·키보드 규칙은 P3에서 CMP로 명세한다.
> **텍스트 200% 확대 시의 줄바꿈·오버플로 규칙은 P3가 정의한다.**
> **`aria-current="page"` 대상**: GNB 항목(전 구간) + `≥1280px` 헤더 주 CTA 버튼. 자기 참조 화면에서는 이동 링크로 강조하지 않는다(§3.0 G-6 ①).

## 4. 주요 사용자 흐름 (15건)

> 각 흐름에 **차수**와 **로그인 상태**를 표시한다. 흐름 안에서 로그인 상태에 따라 갈라지는 지점만 분기로 적고, 화면마다 상태별 서술을 반복하지 않는다.

### Flow-1: 신규 방문자 — 검색 유입 → 신뢰 확인 → 전환 **(핵심 전환 흐름)** · 1차·2차

| 단계 | 화면 | 사용자 행동 | 다음 화면 |

| 2 | SCR-001 | 첫 화면에서 스튜디오가 어디서 무엇을 하는지 확인한다 | SCR-001(스크롤) 또는 즉시 전환 |
| 3 | SCR-001 | 강점·수업 유형·강사 미리보기·위치 요약을 훑는다 | SCR-002 / SCR-003 / 전환 |

- 소문자 영문 kebab-case, 한글·공백·대문자 금지.
- 후행 슬래시 없는 형태로 **한 형태로 통일**한다. 플랫폼이 지원하면 301 정규화, 지원하지 않으면 canonical로 보완한다(확정은 P4·P7).
- 대표 주소(www 유무)는 `[TBD — T-A]`. 결정되면 나머지 한쪽을 301로 보낸다.
- 도메인은 `[TBD — T-A]`. canonical·sitemap·OG url에 쓰이므로 오픈 전 확정 필수.

**영역별 접두어 (v0.5 신설)**

| 접두어 | 영역 | 인증 | 색인 |
|---|---|---|---|
| (없음) `/`, `/instructors`, `/location`, `/privacy`, `/terms` | 공개 정보 | 없음 | 색인 |
| `/consult`, `/consult/complete`, `/consult/lookup` | 공개 — 상담 | 없음 | `/consult`·`/consult/lookup`만 색인 |
| `/signup`, `/login`, `/password/*` | 공개 — 계정 | 없음 | **`noindex`** |
| `/mypage/**` | 회원 전용 | 로그인 | **`noindex`** |
| `/booking`, `/booking/**` | 회원 전용 | 로그인(`/booking`은 안내 상태 허용) | **`noindex`** |
| `/admin/**` | 관리자 전용 | 관리자 로그인 | **`noindex`** |

**식별자 규칙 (REQ-N-R-010 — 반드시 지킨다)**

| 규칙 | 내용 |
|---|---|
| **연번 ID 금지** | `/mypage/bookings/123`·`/admin/consults/45` 같은 **추측 가능한 연번 식별자를 쓰지 않는다.** 마이페이지·관리자 상세 URL 100건 표본에서 연번 증가 0건이어야 한다 |
| **예약번호·신청번호를 URL에 넣지 않는다** | `YP-A7KD-M2XF`는 **표시·전화 응대용**이며 URL 경로·쿼리스트링에 쓰지 않는다. 웹 서버 액세스 로그(= 비통제 경로)에 남으면 REQ-N-R-010 ③ 검색에서 결함이 된다 |
| **대신 `{ref}` = 비연번 공개 식별자** | **UUID v4 등 "시간 순서·인접성이 추론되지 않는 난수 식별자"** 를 URL에 쓴다. 형식 확정은 P4 기술 설계(§8 확인 필요 #2). 항상 **소유자 검사**를 함께 수행한다(REQ-N-M-003).<br>⚠ **ULID는 후보에서 제외한다** (v0.6 — developer R1 #2): ULID 앞 10자는 밀리초 타임스탬프라 **연속 생성분이 사전순으로 단조 증가하고 긴 공통 접두어를 공유**한다. `REQ-N-R-010` ④의 판정("상세 URL 100건 표본에서 연번으로 증가하는 식별자 0건")을 정렬 기준으로 수행하면 **단조 증가로 잡혀 결함 판정이 갈리고**, `{slotRef}`를 비연번으로 두는 목적(편성 정보의 총량·생성 시각이 추측되지 않게 한다)도 달성되지 않는다.<br>**정렬 성능이 필요하면 내부 PK(BIGINT)를 따로 두고 공개 `{ref}`만 난수로 둔다**(P4 구조 선택 — 기획 변경 불필요) |
| **슬롯 식별자 `{slotRef}`** | 개인정보는 아니지만 같은 규칙으로 비연번을 쓴다(편성 정보의 총량이 추측되지 않도록). **시간 정렬형 ID 금지도 동일 적용** |
| **완료 화면은 식별자를 URL에 담지 않는다** | `/consult/complete`·`/booking/complete`는 고정 경로다. 번호 전달은 **1회용 httpOnly 쿠키 또는 클라이언트 상태**(§8.5 D-3, 유효 시간 잠정 30분) |
| **날짜는 경로에 허용 (형식 제약 필수)** | `/booking/2026-10-14`·`/admin/schedule/2026-10`은 개인정보가 아니므로 경로에 쓴다(공유·북마크 편의).<br>⚠ **형식을 `\d{4}-\d{2}-\d{2}`(월 경로는 `\d{4}-\d{2}`)로 제약하고, 형식이 맞지 않거나 실존하지 않는 날짜(예: `2026-02-30`)면 404를 반환한다** (v0.6 — developer R1 #4). 제약이 없으면 `/booking/abcd` 같은 임의 경로가 날짜 화면으로 라우팅되어 **200 응답 + 오류 본문(소프트 404)** 이 되고, `REQ-N-013`(404 상태 코드 실제 반환·소프트 404 금지)·`REQ-F-006`(끊긴 링크 0건) 판정에 직접 걸린다.<br>같은 깊이의 정적 세그먼트(`slots`·`complete`·`week`·`day`)는 날짜 형식과 겹치지 않아 추가 조치가 필요 없다(라우터는 정적 우선으로 매칭한다) |
| **재설정 토큰** | `/password/reset/confirm?t={token}` — 1회용·30분 만료. `noindex` + **`Referrer-Policy: no-referrer`** 를 함께 적용해 외부로 새지 않게 한다.<br>⚠ **외부 유출 차단만으로는 부족하다** (v0.6 — developer R1 #3): **쿼리스트링의 토큰은 자기 서버의 웹 액세스 로그에 그대로 남는다.** `REQ-N-R-010` ⓐ(공개·비통제 경로) 금지 목록에 **"비밀번호 재설정·이메일 인증 등 1회용 토큰"을 추가**했다. 전달 방식은 §8.5 **D-3**의 3선택지 중 P4가 정한다 — ⓐ 프록시 로그 포맷에서 쿼리 제거 / **ⓑ 링크 진입 즉시 토큰을 세션 바인딩 1회용 상태로 교환하고 깨끗한 URL로 리다이렉트(기준안)** / ⓒ 프래그먼트 사용 |

- **회원·관리자 영역에는 구조화 데이터를 넣지 않는다**(REQ-N-A-002, REQ-N-L-005 — 색인 대상이 아니다).
- **예약 관련 스키마(`Reservation`·`Event`)는 쓰지 않는다** — 개인 예약 정보가 마크업으로 노출될 위험이 있고 색인 대상 화면에 예약 데이터가 없다.
- 지점이 2곳 이상이면 구조 변경 필요(§8.5 D-38). 리뷰·평점·수강생 수 등 **검증되지 않은 값은 넣지 않는다.**

### 6.5 크롤링·인덱싱 — 영역 기준 (v0.5 재작성)

| 경로 | 색인 | sitemap | robots.txt |
|---|---|---|---|
| `/`, `/instructors`, `/location`, `/privacy`, `/terms`, `/consult`, `/consult/lookup` | 색인 허용 | **포함** | 허용 |
| `/consult/complete`, `/signup`, `/signup/complete`, `/login`, `/password/*` | **`noindex` 메타** | 제외 | **Disallow 하지 않음** |
| `/mypage/**`, `/booking`, `/booking/**` | **`noindex` 메타** | 제외 | **Disallow 하지 않음** (REQ-N-L-005) |
| `/admin/**` | **`noindex` 메타** | 제외 | **Disallow 하지 않음** (REQ-N-A-002) |
| 404 · 5xx | `noindex` | 제외 | — (정확한 상태 코드 반환) |
| `robots.txt` | — | sitemap 위치 명시 | **Disallow 규칙 없음** |

> **왜 robots.txt Disallow를 쓰지 않는가** (v0.2부터 유지된 결론, v0.5에서 회원·관리자로 확대): robots.txt로 크롤링을 막으면 크롤러가 페이지를 읽지 못해 `noindex` 메타를 볼 수 없고, 외부에 링크가 노출되면 **URL만 색인되어 의도와 반대 결과**가 난다. 또 공개 파일인 robots.txt의 Disallow는 `/admin` 경로의 존재를 알리는 부작용이 있고, **인증으로 막힌 경로에는 실익이 없다.** robots Disallow는 `noindex`를 넣을 수 없는 경로(비HTML 응답 등)에만 쓴다.
> **2차 전환 판정(TR-11)**: sitemap에 `/mypage`·`/booking`·`/admin` 경로가 **0건**이고 robots.txt에 해당 Disallow가 **0건**이어야 한다.

### 6.6 404 · 오류 화면

- **404**: "요청하신 페이지를 찾을 수 없습니다." / "주소가 바뀌었거나 삭제된 페이지일 수 있습니다." 제공 링크 = 홈 · (차수별 주 CTA) · 오시는 길 · 전화 걸기. **HTTP 404 상태 코드를 실제로 반환**한다(소프트 404 금지).
- **관리자 영역 경로의 404는 관리자 셸 안에서 보여주고 공개 GNB를 노출하지 않는다**(REQ-F-060).
- **5xx·점검(SCR-009, Could)**: 404 템플릿을 재사용해 문구만 교체하고 전화 링크를 포함한다. 새 SCR을 만들지 않는다.
