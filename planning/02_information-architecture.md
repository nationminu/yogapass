# 정보구조 (IA) — 강남 요가패스 홈페이지

> **읽는 법**
> - 메뉴 페이지는 **6종으로 고정**이다(계획서 §2.1 페이지 추가 원칙). 폼 완료·404 같은 보조 화면은 페이지 수에 넣지 않는다.
> - **예약(SCR-004)·예약조회(SCR-005)·예약 완료(SCR-007)는 예약 영역**이며 ADR-001 결정 대기다. 본문은 기준안 A'-1 기준이고, 선택지별 IA 차이는 §7에 있다.
> - 문의 폼 위치는 **Q4 회신 전 가정**이다(§2.3).
> - 모든 사실 정보는 `[TBD: 고객 확인 필요]`다.
> - **v0.2 (R1 반영) 중요 변경**: ① 하단 고정 바 규칙은 이 문서가 아니라 **`02_requirements.md` §3.0**이 단일 기준이다(§5.1에서 참조). ② **SCR별 관련 REQ 목록은 `02_requirements.md` §9가 유일한 기준선**이며 §3은 이를 참조만 한다(qa R1 #4).
> - **v0.3 (R2 반영) 중요 변경**: ① **768px에서는 헤더에 예약 강조 버튼을 두지 않는다**(§2.1·§2.3·§5 — 요구사항 §3.0 G-8). ② **가상 키보드 활성 중에도 하단 고정 바를 유지한다** — v0.2의 "일시 숨김"은 삭제됐다(요구사항 §3.0 G-9). ③ §6.3 description 초안 1건 수정·글자 수 2건 정정.

## 1. 사이트맵

```
홈 / 메인 (SCR-001)  —  /
├── 요가 강사 소개 (SCR-002)  —  /instructors
├── 오시는 길 (SCR-003)  —  /location
│   └── [섹션] 문의하기 (일반 문의 폼)  —  /location#contact   ※ 위치는 Q4 회신 전 가정
├── 예약 (SCR-004)  —  /reservation                      ▲ 예약 영역 (ADR-001 대기)
│   └── 예약 신청 완료 (SCR-007, 보조)  —  /reservation/complete   ▲ 예약 영역
├── 예약조회 (SCR-005)  —  /reservation/lookup           ▲ 예약 영역
└── 개인정보 처리방침 (SCR-006)  —  /privacy

[보조] 404 (SCR-008)  —  존재하지 않는 모든 경로
```

- 계층은 **1depth 평면 구조**다. 페이지가 6개뿐이고 모바일에서 2depth 메뉴는 조작 부담만 늘리므로 하위 메뉴를 두지 않는다.
- 예약 완료(SCR-007)는 예약 페이지의 후속 화면이므로 URL을 `/reservation/` 하위에 둔다. 메뉴에는 노출하지 않는다.
- 예약조회도 예약과 같은 맥락이라 `/reservation/lookup`으로 두되, **주 메뉴에는 독립 항목으로 노출한다**(고객이 5개 페이지로 요청했고, 신청자가 직접 찾아와야 하는 화면이기 때문).

### 2.1 GNB (주 메뉴)
| 1depth | 2depth | SCR ID | URL | 비고 |
|---|---|---|---|---|

| 예약 | — | SCR-004 | `/reservation` | **강조 버튼 형태로 표시** (전환 목표, REQ-F-003) ▲ 예약 영역 |
| 예약조회 | — | SCR-005 | `/reservation/lookup` | ▲ 예약 영역 |

- 데스크톱(1280px 이상): 로고 좌측, 메뉴 5개 중앙·우측, "예약 신청" 버튼을 채운 버튼으로 강조. **헤더 예약 CTA는 이 구간에만 있다.**
- 태블릿(768px): 메뉴 텍스트 축약 없이 유지. **헤더에 예약 강조 버튼을 두지 않는다**(전화 아이콘 + GNB만) — 768px에도 하단 고정 바가 상시 노출되므로(요구사항 §3.0 G-1) 헤더 버튼을 함께 두면 같은 화면에 예약 CTA가 2개가 되어 시선이 분산되고, SCR-004에서 헤더 버튼이 자기 자신을 가리키는 문제도 남는다. **예약 CTA는 고정 바가 전담한다**(요구사항 §3.0 **G-8**, designer R2 #2).
- 모바일(360px): 로고 + 햄버거 버튼. 햄버거를 열면 5개 항목 전체 노출. 헤더에는 전화 아이콘만 남기고, 예약 CTA는 **하단 고정 바**로 이동(§2.3).
- GNB '예약' 항목 자체는 전 뷰포트에서 메뉴로 유지된다. 위 규칙은 **헤더의 "예약 신청" 강조 버튼(CTA)** 에만 적용된다.
- 개인정보 처리방침은 GNB에 넣지 않고 푸터에만 둔다(전환 동선을 방해하지 않기 위해). 전 페이지에서 접근 가능하므로 REQ-F-005를 충족한다.

## 3. 페이지 목록

> v0.1에서는 이 표·화면정의서 화면 목록·각 SCR 상세가 서로 다른 목록을 갖고 있어 추적 매트릭스의 기준선이 없었다. v0.2부터 이 표는 **§9.2를 참조만** 하고 자체 목록을 유지하지 않는다.
> 전 화면 공통 적용 REQ(REQ-F-001~006, REQ-N-001~030, REQ-C-001·009·015~018)는 §9.1에 있으므로 화면별로 반복하지 않는다.

## 4. 주요 사용자 흐름

### Flow-1: 신규 방문자(U-1) — 검색 유입 → 신뢰 확인 → 예약 신청 **(핵심 전환 흐름)**
| 단계 | 화면 | 사용자 행동 | 다음 화면 |
|---|---|---|---|
| 1 | (외부) 검색 결과 | "강남 요가" 등으로 검색해 사이트를 찾는다 | SCR-001 |
| 2 | SCR-001 | 첫 화면에서 스튜디오가 어디서 무엇을 하는지 확인한다 | SCR-001 (스크롤) 또는 SCR-004 (즉시 전환) |
| 3 | SCR-001 | 강점·강사 미리보기·위치 요약을 훑는다 | SCR-002 또는 SCR-003 또는 SCR-004 |
| 4 | SCR-002 | 강사 경력·담당 수업을 보고 신뢰를 판단한다 | SCR-004 |
| 5 | SCR-003 | 위치·교통·운영시간이 다닐 만한지 확인한다 | SCR-004 |
| 6 | SCR-004 | 신청 항목을 입력하고 개인정보 동의 후 제출한다 | SCR-007 |
| 7 | SCR-007 | 예약번호를 확인·보관하고, 스튜디오 연락 안내를 읽는다 | 종료 또는 SCR-005 |

> **전환 거리 원칙**: 어떤 화면에서든 예약·전화까지 **1번의 조작**(하단 고정 바 또는 고정 헤더 버튼)으로 도달한다(REQ-F-003). 문의는 2번 이내(푸터·본문 "문의하기" → 폼)다. 요구사항 §1 개요와 같은 기준이다 (qa R1 #18 반영 — v0.1의 "2번 이내"와 불일치 해소).
> **이탈 지점 주의**: 4·5단계에서 정보가 `[TBD]`로 비어 있으면 신뢰가 깨져 이탈한다 → REQ-N-023(오픈 시 TBD 0건)과 직결.

### Flow-2: 신청자(U-2) — 예약조회 ▲ 예약 영역
| 단계 | 화면 | 사용자 행동 | 다음 화면 |

### 6.5 크롤링·인덱싱
| 경로 | 처리 |
|---|---|
| `/`, `/instructors`, `/location`, `/reservation`, `/reservation/lookup`, `/privacy` | 색인 허용, sitemap 포함 |
| `/reservation/complete` | **`noindex` 메타만 적용**, sitemap 제외, **크롤 허용(robots.txt Disallow 하지 않음)** (개인 신청 결과 화면) |
| 404 | `noindex`, 404 상태 코드 반환 |
| `robots.txt` | 전체 허용 + sitemap 위치 명시. **Disallow 규칙 없음** |

> **v0.1 수정 (developer R1 #3③, qa R1 #9)**: v0.1은 `/reservation/complete`에 `noindex`와 robots `Disallow`를 **동시에** 지정했다. robots.txt로 크롤링을 막으면 크롤러가 페이지를 읽지 못해 `noindex` 메타를 볼 수 없고, 외부에 링크가 노출되면 오히려 URL만 색인되어 의도와 반대 결과가 난다. **`noindex` 유지 + Disallow 제거**로 확정한다. robots Disallow는 `noindex`를 넣을 수 없는 경로(예: A'-2b 관리자 영역의 비HTML 경로)에만 쓴다.
> A'-2b로 결정되면 `/admin/*`은 `noindex` + 인증 차단을 기본으로 하고, robots Disallow는 경로 존재를 알리는 부작용을 고려해 §7 결정 시 다시 판단한다.
