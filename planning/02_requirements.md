# 요구사항 정의서 — 강남 요가패스 홈페이지

> **읽는 법 (검토자·PM용)**
> 1. **문서 구성이 템플릿과 조금 다르다.** G1 조건 C-3에 따라 **예약·예약조회 요구사항을 §4에 별도 묶음**으로 분리했다(`REQ-F-R-*`, `REQ-N-R-*`, `REQ-C-R-*`). ADR-001이 결정되면 §4만 정리하면 되고 §3·§5·§6은 손대지 않는다.
> 2. **§4는 A'-1(계획 기준안·가정)으로 본문을 썼다.** A / A'-2a / A'-2b / C를 고를 때 무엇이 추가·삭제·변경되는지는 §4.5 차이표에 있다. **B(자체 예약 시스템)는 계획 재산정 대상이라 병기하지 않는다**(계획서 §4.2).
> 3. **고객 확인 질문 27건은 아직 회신 전이다.** 주소·전화·강사·요금·운영시간·사업자 정보 등 사실 정보는 하나도 확정되지 않았고, 모두 `[TBD: 고객 확인 필요]`로 두었다. 확인 항목과 영향 범위는 §8에 모았다.
> 4. **요구사항 총 111건** — 기능 57건(공통 38 + 예약 영역 19), 비기능 33건(공통 27 + 예약 영역 6), 콘텐츠 21건(공통 19 + 예약 영역 2). 우선순위 집계는 §7.

## 1. 개요
| 항목 | 내용 |
|---|---|
| 사이트명 | 강남 '요가패스' 홈페이지 (YOGAPASS) |
| 사이트 목적 | **예약 문의 증가** (고객 명시, CR-000). 강남 인근에서 요가 수업을 찾는 사람이 스튜디오를 신뢰하고 예약·문의까지 도달하게 한다 |
| 대상 사용자 | §2 참조 |
| 핵심 전환 목표 | ① 예약 신청서 제출 ② 일반 문의 제출 ③ 전화 걸기. 이 세 가지를 모든 화면에서 2번 이내의 조작으로 도달할 수 있게 한다 |
| 페이지 범위 | 메뉴 페이지 6종 (메인, 요가 강사 소개, 오시는 길, 예약, 예약조회, 개인정보 처리방침) + 보조 화면(예약 완료, 404). 계획서 §2.1 페이지 추가 원칙에 따라 페이지를 늘리지 않는다 |
| 톤·이미지 | 화이트·블루 기반, 신뢰감. 보유 로고 사용. 사진 없음 → §6 REQ-C-013 이미지 조달 방안 |

| 미확정 핵심 | **예약·예약조회 기능 범위(ADR-001, 09-16 결정 목표)** — §4 |
