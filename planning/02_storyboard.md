# 화면정의서 (스토리보드) — 강남 요가패스 홈페이지

## 공통 규칙
- 공통 헤더·푸터·하단 고정 바: `02_information-architecture.md` §5 참조. 각 화면 정의에서는 반복하지 않는다.
- **하단 고정 바·고정 헤더의 단일 기준은 `02_requirements.md` §3.0(G-1~G-11)이다** (designer R1 #1·#2, qa R1 #1 반영).
  - **전 8개 화면(SCR-001~008)의 360·768px에 항상 표시**한다. 폼 화면에서도 숨기지 않는다. 아래 모든 와이어프레임에 `▣ 고정 바`를 표기했다.
  - 겹침은 **여백 확보**로 처리한다 — 폼 화면 본문 하단 최소 72px, 제출 버튼과 고정 바 사이 16px 이상.
  - **SCR-004(예약)에서만** 고정 바가 "전화 문의" **전폭 1버튼**으로 바뀐다. SCR-005·006·007·008은 기본 2분할이다.
  - 가상 키보드가 올라온 동안에는 고정 바를 일시 숨긴다(여백은 유지).
- **각 화면의 "관련 REQ"는 `02_requirements.md` §9.2(매핑 기준선)의 값을 그대로 옮긴 것이다** (qa R1 #4 반영). 불일치가 생기면 **§9가 맞고 이 문서를 고친다.** 전 화면 공통 적용 REQ(REQ-F-001~006, REQ-N-001~030, REQ-C-001·009·015~018)는 §9.1에 있으므로 화면별로 반복하지 않는다.
- **폼이 있는 화면(SCR-003 `#contact`·SCR-004·SCR-005) 공통 상태 규칙**: 전송·조회 중에는 버튼 비활성 + 진행 문구 + 중복 제출 차단, 결과(성공·오류) 표시 직후 결과 블록(`tabindex="-1"`)으로 **포커스를 이동**한다 (IA §5, designer R1 #8).
- **문구 표기**: 실제 문구 초안은 "큰따옴표". 고객만 아는 사실 정보는 `[TBD: 고객 확인 필요 — Qnn]`.
- **이미지 표기**: `[IMG: 설명 · 권장 비율 · 제공 주체]`
- **모바일 우선**: 와이어프레임은 360px 기준으로 그리고, 768·1280px 변화는 "반응형 변화" 항목에 적는다.
- **문구 초안의 성격**: 아래 문구는 designer·developer가 그대로 쓸 수 있는 초안이다. 다만 **사실(연혁·수강생 수·실적·수상)은 한 글자도 넣지 않았다.** 고객 회신 후 REQ-C 항목으로 교체한다.
- ▲ 표시가 있는 화면·섹션은 **예약 영역(ADR-001 결정 대기)** 이다. 본문은 기준안 A'-1 기준이며, 선택지별 차이는 §마지막 "예약 영역 화면 차이표"에 있다. **B는 병기하지 않는다.**

## 예약 영역 화면 차이표 (ADR-001 결정 대기 — G1 조건 C-3)
> 본문(SCR-004·005·007)은 **A'-1 + 예약번호 전달 수단 (a) 완료 화면 표시** 기준이다.
> 결정 후 이 표를 보고 해당 화면을 정리하고 이 절을 삭제한다. **B는 병기하지 않는다.**

### (1) 화면 단위 차이
| 화면 | A 접수형 | **A'-1 (본문)** | A'-2a (기존 도구) | A'-2b (관리 화면) | C 외부 예약 서비스 |
|---|---|---|---|---|---|
| SCR-004 예약 | 동일 (저장·예약번호 없음) | 본문 그대로 | 본문 그대로 | 본문 그대로 | **전면 교체** — 안내 + "예약 페이지로 이동" 버튼(또는 임베드). 폼 섹션 3 삭제 |
| SCR-005 예약조회 | **폼 삭제** → 안내 화면: "신청해 주신 내용은 스튜디오에서 확인 후 전화로 연락드립니다." + 전화 링크 + 예약 신청 링크 | 본문 그대로 | 섹션 3에 **상태 배지(접수/확정/취소)** 추가, 섹션 3 안내 박스를 상태 설명으로 교체, 섹션 5 변경·취소 안내 유지 | A'-2a와 동일 | **전면 교체** — 외부 서비스 조회 페이지 이동 안내 |
| SCR-007 완료 | 섹션 2(예약번호) 삭제, 섹션 5의 "예약 조회하기" 삭제. "스튜디오에서 연락드립니다" 안내 중심 | 본문 그대로 | 본문 그대로 | 본문 그대로 | **화면 삭제** (외부 서비스 완료 화면 사용) |
| 신규 화면 | 없음 | 없음 | 없음 | **SCR-009 관리자 로그인 / SCR-010 신청 목록 / SCR-011 신청 상세·상태 변경** (전부 `noindex`·robots Disallow) | 없음 |

### (2) 본문 문구가 바뀌는 지점
| 위치 | A'-1 (본문) | A'-2a·A'-2b | C |
|---|---|---|---|
| SCR-005 섹션 3 안내 박스 | "'접수 완료'는 예약이 확정되었다는 뜻이 아닙니다. 확정·변경·취소는 스튜디오에서 전화로 안내드립니다." | "현재 상태: {접수 완료 / 예약 확정 / 취소}. 변경·취소를 원하시면 전화로 말씀해 주세요." | (외부 서비스 문구 사용) |
| SCR-007 섹션 4 | 동일 문구 유지 | 상태 확인 가능 안내로 교체: "예약조회에서 진행 상태를 확인하실 수 있습니다." | 해당 없음 |
| SCR-004 섹션 2 진행 안내 | "① 신청서 작성 → ② 스튜디오 확인 연락 → ③ 방문" | 동일 (조회로 상태 확인 가능 문구 추가) | 외부 서비스 이동 고지로 교체 |

### (3) 예약번호 전달 수단(Q25)별 화면 차이 — A' 계열 안에서
| 수단 | SCR-004 | SCR-005 | SCR-007 |
|---|---|---|---|
| **(a) 완료 화면 표시 (본문)** | 기준 항목 | 예약번호 + 휴대폰 입력 | 예약번호 강조 + 복사 버튼 |
| (b) 신청자 이메일 안내 | **"이메일" 입력 항목 추가**(필수), 동의 문구에 이메일 추가 | 동일 | "입력하신 이메일로도 안내를 보내드렸습니다." 문구 추가 |
| (c) 문자 발송 | **범위 밖** (계획서 §2.2). 선택 시 CR로 별도 산정 | — | — |
| (d) 이름 + 휴대폰 조회 | 기준 항목 | **입력 항목이 "이름 + 휴대폰 번호"로 교체**, 예약번호 입력 삭제. 섹션 4(분실 안내) 삭제. **동명이인·복수 신청 처리 규칙(요구사항 §4.5 (3)에서 확정, 잠정)**: 같은 이름 + 같은 번호로 신청이 여러 건이면 **가장 최근 1건만 표시** + "이전 신청 내역은 전화로 문의해 주세요" 안내. 이름만 같고 번호가 다르면 조회되지 않는다 | 예약번호 강조 약화, "이름과 휴대폰 번호로 조회하실 수 있습니다" 안내로 교체 |

> (d)는 본인 확인이 약해지므로 시도 제한(REQ-F-R-024)과 마스킹(REQ-F-R-021)을 강화해야 한다(RSK-015).
