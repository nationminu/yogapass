**권고의 근거**

1. **developer가 고친 10건은 전부 실제 실행으로 해소를 확인했고 회귀 0건이다.** 재오픈은 없다. 사이클 1의 Major 1건·Minor 8건·Trivial 1건이 모두 사라졌고, 1차에서 Fail이던 Must REQ 6건(REQ-N-006·010·011·016·020·033)과 콘텐츠 REQ 1건(REQ-C-016)이 Pass로 전환됐다.
2. **품질 지표는 1차보다 전면 상승했다** — Lighthouse 4지표 전건 99~100(권장사항 메인 92→**100**), HTML 검증 오류 5→**0건**, 콘솔 오류 2→**0건**, 320px 가로 스크롤 4화면→**0화면**, 터치 타깃 미달 6종→**0종**.
3. **다만 G5 통과 기준(Critical·Major 0건)은 아직 충족하지 못한다.** 사이클 2에서 **DEF-011(Major)** 을 새로 발견했다 — viewport 메타에 `interactive-widget=resizes-content`가 **5화면 전건 누락**이다. **이번 수정으로 생긴 회귀가 아니라 1차 구현(`c6fa91f`) 시점부터 있었고 사이클 1이 놓친 잔존 결함**이다(1차 TC-009는 폴백 스크립트와 `--fixed-bar-h`만 확인하고 메타 토큰을 대조하지 않았다).
4. **DEF-011은 "지금 당장의 사용자 영향"은 관측되지 않지만 "오픈 전 반드시 해소"다.** 1차의 유일한 폼 화면 `/location`이 자기 참조 + 대표 전화 `[TBD]`라 고정 바를 렌더하지 않아(S3) 현재는 가릴 바가 없다. **대표 전화(T-E)가 확정되는 순간 바가 렌더되어 실제 결함이 된다.** 요구사항 §3.0 G-9는 *"지정하지 않으면 Android 기본값에서도 고정 바가 가려진다"* 로 결과를 단정하고, REQ-N-002는 *"가려지면 '허용'이 아니라 결함"* 이라고 못박는다.
5. **수정 비용은 속성 1개**이며, 재검증은 정적 확인(⑤-1)만으로 닫을 수 있다(약 10분).

**따라서 PM께 드리는 선택지는 두 가지다.**
- **(권고) ⓐ DEF-011 수정 → 정적 재확인(사이클 3, 부분 검증) → G5a 승인.** 남은 작업이 1줄이라 일정 영향이 사실상 없다.
- ⓑ **DEF-011을 "오픈 전 필수(P7 차단 조건)"로 등록하고 G5a를 조건부 승인**한 뒤 P6로 진행. 이 경우 **P7 배포 승인 전에 반드시 해소·재확인**해야 하며, 미해소 상태의 운영 배포는 REQ-F-003·REQ-N-002 위반이다.

> **오픈을 막는 진짜 요인은 여전히 품질이 아니라 입력이다.** 고객 제공 값 8묶음 미수령으로 **REQ 20건이 Block**이고, 그중 12건이 콘텐츠 REQ로 REQ-N-023 ②의 1차 필수 노출 목록과 그대로 겹친다. 이것은 **결함이 아니라 입력 미확보**이며 pmo의 일정 안건이다(§6).

### 실행상 주의 (다음 사이클·devops 인계)

- 운영 미리보기를 새로 만들 때 `.env.prodcheck`의 **`DJANGO_SETTINGS_MODULE=config.settings.production`** 을 반드시 함께 바꾼다(developer 인계 메모대로 적용해 이번에 문제 없었다).
- **운영 미리보기 스택은 `migrate`를 자동 실행하지 않는다.** 기동 직후 DB가 비어 있어도 5화면이 200을 준다(설계 의도 — 마이그레이션은 `deploy.sh` 3단계 소관). 콘텐츠 판정 전에 `migrate` + `seed_content`를 직접 돌려야 한다.
- **`qa_purge_test_data`는 `name`·`message`가 `TEST-`로 시작하는 행만 지운다**(기술 설계 §10.4). 이번 사이클에 qa가 `QA2-` 접두어를 써서 걸리지 않았다 — **도구 결함이 아니라 절차 착오**다. 다음 사이클부터 시험 데이터는 반드시 **`TEST-` 접두어**를 쓴다.
- `docker compose exec app …` 은 일회용 컨테이너를 집을 수 있다(compose v2.19.1). 운영 컨테이너 판정 시 `docker exec <이름>` 으로 지정한다.
- `tests/browser/layout-check.js`(developer 제공)를 qa가 직접 실행해 **자체 측정과 일치**함을 확인했다. 다만 이 도구는 **`/nope`의 자기 404 응답을 콘솔 오류 위반으로 계수**해 "위반 4건"으로 끝난다. 판정에는 영향이 없지만 **도구의 예외 처리 보완을 권고**한다(developer).

## 9. 권고

1. **DEF-011을 즉시 처리하고 정적 재확인으로 닫는다.** 이것이 G5a를 "합격"으로 만드는 유일한 잔여 조건이다. 재발 방지 테스트 1건(전 화면 `<head>` 토큰 존재)을 함께 넣기를 요청했다.
2. **§4.3의 확인 요청 3건(①②③)은 designer·planner 확인이 필요하다.** 특히 **②(푸터 링크 인접 간격 0px)** 는 REQ-N-006 ②의 "인접 8px" 규칙을 세로 링크 목록에도 적용할지의 **규칙 해석 문제**라 qa가 단독 판정하지 않았다. 결론이 나기 전까지 이 항목은 **판정 보류**이며, "적용한다"로 결론나면 새 결함이 될 수 있다.
3. **TC-103(REQ-N-011)은 조건부 Pass다.** `/location`의 h1이 `"오시는 길"`이라 '강남'·'요가'를 담지 않지만, **승인된 스토리보드 §SCR-003이 h1을 그렇게 규정**하고 바로 아래 리드 문장이 `"강남 요가패스를 찾아오시는 방법을 안내합니다."` 다. 구현은 승인 산출물을 따랐다. **planner가 REQ-N-011의 'h1' 요건과 스토리보드의 h1 문구 중 무엇이 정본인지 확인**해 주기를 요청한다.
4. **메인 h1은 현재 `"강남 요가패스"`(폴백)다.** 고객 헤드라인(T-G)이 들어오면 h1 문자열이 바뀌므로 **REQ-N-011이 그때 다시 깨질 수 있다.** 콘텐츠 수령 시 재검증 항목으로 등록한다.
5. **Lighthouse 404 측정(M-2 ③)은 현 도구로 실행 불가능한 기준**임이 두 사이클 연속 확인됐다. 2차 게이트 전에 planner와 기준을 정리하기를 권고한다(측정 대상 제외 + 정적 점검 대체).
6. **devops에게**: DEF-007이 닫혔으므로 롤백 경로의 선행 조건은 해소됐다. 남은 P7 진입 선행 조건은 **`devops/07_deploy-plan.md`의 권한자 목록·백업 보관 위치 초안**(L-7)이다.
7. **pmo에게**: 오픈 차단 요인은 **고객 값 8묶음 미수령(REQ 20건 Block)** 이다. G5a 게이트 문서에 **T-A~T-H 수령 일정**을 안건으로 올려 주기를 요청한다.
8. **다음 사이클(3차)이 열린다면 최소 범위**: ⓐ DEF-011 정적 재확인 ⓑ §4.3 확인 결과 반영분 ⓒ Edge·Firefox 보완(L-3) ⓓ §9.6 ⑥ 재실행(L-14) ⓔ 복구 리허설(L-15).
