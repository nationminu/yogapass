# 회의록: 강남 요가패스 홈페이지 프로젝트 킥오프

> **회의 방식**: 문서 기반 비동기 킥오프. 서브에이전트는 서로를 직접 호출할 수 없어서, pmo가 고객 요청(CR-000)을 분석하고 계획서 초안(`pm/01_project-plan.md` v0.1)과 함께 이 회의록을 작성했다.
> planner·developer 의견은 P1 교차 검토(R1, `shared/reviews/`)로 받는다. 다른 팀 의견은 아직 받지 않았으므로 이 회의록에 적지 않았다. 총괄 PM의 결정은 G1 게이트와 ADR-001에서 받는다.
>
> **갱신 메모 (2026-09-11, pmo)**: 계획서 v0.2(R1 리뷰 반영)와 맞추기 위해 질문 번호·건수, ADR-001 입력 질문, 예약 선택지 이름(A'-1/A'-2a/A'-2b), 압축 옵션(O-6), 액션 아이템을 갱신했다. 논의 경위는 바꾸지 않았고, 바뀐 곳에는 "(v0.2 갱신)"을 표시했다. 근거: `shared/reviews/P1_project-plan_planner_r1.md`, `shared/reviews/P1_project-plan_developer_r1.md`
>
> **갱신 메모 (2026-09-11, pmo, v0.3)**: 계획서 v0.3(R2 리뷰 반영)에 맞춰 A' 계열 추가 작업일, 일정 대응안 S-1 전제 조건, 고객 질문 보완(Q5 ③ 등), 액션 아이템 상태를 갱신했다. 논의 경위는 바꾸지 않았고, 바뀐 곳에는 "(v0.3 갱신)"을 표시했다. 근거: `shared/reviews/P1_project-plan_planner_r2.md`, `shared/reviews/P1_project-plan_developer_r2.md`

## 1. 목적
- 고객 요청(CR-000)의 해석과 프로젝트 범위·일정·리스크 초안을 전 팀이 같은 기준으로 공유한다.
- 착수 직후 고객에게 확인할 사항과 PM 결정 사항을 확정해 요청한다.

## 2. 안건
1. 고객 요청 해석 (명시 / 추론 / 확인 필요)
2. 범위와 핵심 쟁점: 예약·예약조회 기능 범위, 문의 폼과 예약의 관계
3. 일정·마일스톤 (10월 말 오픈)
4. 고객 확인 사항과 콘텐츠·이미지 수급
5. 리스크
6. 소통 규칙과 다음 할 일

## 4. 결정 사항
- 이번 킥오프에서 **확정된 결정은 없다.** 아래는 PM 결정 전까지 쓰는 **계획 가정**이다.
  - 예약 기능 기준안 A'(신청 접수 + 접수 조회) — (v0.2 갱신) A'-1 접수 확인형(상태 변경·관리 화면 없음). ADR-001(예정)에서 결정
  - 문의 폼은 예약과 별도인 일반 문의 폼
  - 오픈 목표일 2026-10-27, 오픈 마감 10-30 — (v0.2 갱신) 현행 WBS는 A·C안 분량 기준
  - 한국어 단일 언어, CMS 없음, 알림은 이메일
- 결정이 필요한 사항(PM): ① 예약·예약조회 기능 범위(ADR-001) ② 목표 오픈일 확정 ③ 고객 질문 발송 ④ 일정 압축 옵션 사용 여부. (v0.2 갱신) ⑤ A' 계열 선택 시 일정 대응안 S-1~S-4 ⑥ Safari·iOS 검증 수단(G3까지)
