# 리뷰: 프로젝트 계획서 v0.2 — developer (R2)

## 1. 총평
- R1 Must 2건은 **모두 해결**됐다. A'가 A'-1 / A'-2a / A'-2b로 나뉘었다. 상태 변경 수단과 예약번호 전달 수단은 ADR-001 결정 항목과 Q24·Q25로 올라갔다. "현행 WBS는 A·C 분량이고, A' 계열은 10-27 오픈 불가"라는 평가와 선택지별 예상 오픈일, 일정 대응안 S-1~S-4도 들어갔다. Should·Could 14건도 모두 반영된 것을 확인했다.
- planner R1 #1(상태 변경 없는 A'-1)과 developer R1 #1(기존 도구 / 관리 화면)의 분류 차이는 A'-2a·A'-2b 세분과 §4.2 ※ 대응 관계로 정리돼 **충돌이 남아 있지 않다.**
- pmo가 확인을 요청한 환산 2건의 결과는 다음과 같다(부록 B).
  - ① A'-1 공수 차감은 **타당하다.** 다만 "+4~6 이하"는 상한만 적은 값이다. 정확한 값은 전달 수단이 (a)·(d)이면 **+3.5~5작업일(11-02~11-03)**, (b) 이메일이면 **+4~6작업일(11-02~11-04)**이다.
  - ② O-6 적용 시 10-28~10-29는 **조건부로 타당하다.** 서버 측 서비스 선정·계정 준비가 P3 중간(10-02)까지 끝나야 한다. 현행 WBS처럼 계정 준비가 G3(10-07)이면 통합 확인 1일이 P4에 남아 **10-29~10-30(버퍼 0)**이 된다.
- v0.2에서 새로 생긴 문제 가운데 게이트를 막을 오류는 없다. ADR-001(09-16) 결정 자료의 정확도를 높이기 위한 Should 5건과 Could 2건을 지적한다. 판정은 **조건부 승인**이다.
