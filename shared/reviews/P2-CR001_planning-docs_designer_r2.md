# 리뷰: P2 기획 산출물 (CR-001 반영본) v0.6 — designer (R2)

> **범위를 좁힌 확인 검토다.** ① R1 지적 11건이 v0.6 원문에 실제로 들어갔는지 대조 ② 그 반영 때문에 **새로 생긴 모순만** 추가 지적. 문서 전체 재검토·기해결 사항 재론·신규 요구는 하지 않았다.

## 1. 총평

**R1 지적 11건(Must 1 · Should 7 · Could 3)이 전부 반영됐고, 게이트를 막던 Must #1은 해소됐다.** 캘린더 셀은 이제 **규칙(REQ-N-006 ②-1) · 수용 기준(②-2 계산식 + 파생값 45.1px) · 화면정의서(SCR-110 §4·반응형)** 세 곳이 **한 값을 가리킨다** — 규칙 8px vs 수용 기준 2px의 자기모순이 사라졌고, 셀 안 전체 문구도 축약 문구(REQ-C-L-001)로 분리되어 "14px을 지키면 잘리고 줄이면 규칙 위반"인 막다른 길이 없어졌다. 값 복제 4곳도 계산식·REQ ID 참조로 바뀌었고, 권고하지 않았던 관리자 공통 규칙 2곳까지 함께 정리됐다.

**신규 Must는 0건이다.** 새로 발견한 것은 반영 과정에서 딸려 들어온 **산술·표기 정합 2건(Should)** 과 표기 정리 3건(Could)뿐이며, 전부 한 줄 수정이고 **P3 컨셉 시안·디자인 시스템 착수를 막지 않는다.** 둘 중 어느 것도 고쳐지지 않더라도 designer가 P3에서 흡수할 경로를 §4에 함께 적었다. **G2 승인에 디자인 관점의 차단 요소는 없다.**

가장 주의해서 볼 것은 Should #N1이다. 축약 문구 5종 중 **"잔여 {n}"만 폭이 가변인데 근거 문장이 "최대 28px"로 고정 표기**되어 있어, 잔여가 두 자리가 되는 순간 Must #1에서 막 닫은 잘림 문제가 같은 자리에서 다시 열린다.

| `768~1279px` GNB 항목 패딩 | IA §2.1 (#N2) | 패딩 **12px 고정** 토큰. 로고 수령 후 폴백 ①(심볼 44px)부터 적용 |
| `1024~1279px` 관리자 사이드바 아이콘 모드 | SBA SCR-903 §2 | 64px 전환 규칙 + 주 뷰 열 폭 하한(≥120px) 명세 |

## 6. 요약

- **신규 Must: 0건 · Should: 2건 · Could: 3건** (총 5건)
- **R1 지적 11건: 해결 11 · 미해결 0** (Must #1 해소 — 캘린더 셀이 규칙·수용 기준·화면정의서에서 한 값을 가리킨다)
- **판정: 조건부 승인**
- 신규 Should 2건은 **산술·표기 정합**이며 둘 다 한 줄 수정이고, 미반영 시의 P3 흡수 경로를 §4에 적었다. **G2 승인을 미룰 디자인 관점의 사유는 없다.** 다만 #N1의 **{n} 정의(잔여 자리 합계인지 슬롯 수인지)** 한 가지는 designer가 정할 수 없으므로 게이트 문서에 회신 항목으로 남겨 주기를 권한다.
