# 리뷰: P2 기획 산출물 4종 v0.6 (CR-001 회귀) — qa (R2)

> **범위 축소 확인 검토.** R1 지적 12건의 반영 여부 확인 + 그 반영으로 새로 생긴 검증 문제만 본다. 문서 전체 재검토는 하지 않았다. 테스트 도구는 설치·실행하지 않았고, 문서 대조용 Node 스크립트만 임시 디렉토리에서 실행했다(프로젝트에 파일 미생성).

## 1. 총평

**R1 Must 3건은 전부 해소됐고, 그 근거를 R1과 같은 기계 대조를 다시 돌려 확인했다.**

- **Must #1 (§9 추적 누락 11건)** — 정의 REQ 241건과 §9.1~§9.5가 참조하는 REQ 집합의 **차집합 0건**이다. 누락됐던 11건이 전부 §9에 실제로 등록됐고, **보강 경위표를 제외한 §9 본문만으로 대조해도 결과가 같다**(자기 선언으로 메우지 않았다). 반대 방향(§9 할당 REQ → 화면정의서 블록)도 **45화면 전수 누락 0건**으로 회귀가 없다.
- **Must #2 (게이트 판정 모수)** — §7.3 교차표 12칸과 검산 줄 전부가 각 REQ 행의 `차수` 열과 **정확히 일치**한다(1차 35 / 공통 61 / 2차 145, Must 16 / 44 / 126). 1차 모수 96 · 2차 241, 참고값 77 / 212도 재현됐다. §7.3·§7.4·§9 말미의 분모 단위가 **콘텐츠 포함 전건 하나로 통일**됐고, 구 수치(54/39/148, 74, 93)는 v0.6 정정 경위로만 남아 있다.
- **Must #3 (REQ-N-039)** — 차수 `공통` 전환 + 수용 기준 1차/2차 분리 + §5.3 행 갱신 + §8.3 I-8 행 반영까지 네 곳이 같은 값을 가리킨다.

**미반영 1건(REQ-C-001·REQ-C-009·REQ-F-004를 `1차`로 유지)의 사유는 타당하다고 판단한다** — 근거는 §2 표와 §3.1에 적었다. 검증 누락이 생기지 않음을 M-7 규정과 §7.3 모수로 직접 확인했다.

Should·Could 9건도 전부 반영됐고, **R1에서 "판정 불가"로 분류했던 2건(게시 기한 알림 회차 · 강사 비활성 시 미래 슬롯)이 0건이 되어 신규 126건의 수용 기준은 전건 TC 전환이 가능하다.** 신규 지적은 **Could 3건**뿐이며 셋 다 게이트와 무관하고 qa가 P5 테스트 계획에서 흡수할 수 있다. **판정은 승인이다.**

### 3.1 미반영 1건(R1 #2 ②)의 사유 검토 — **타당. 수용한다**

planner는 `REQ-C-001`(로고) · `REQ-C-009`(대표 전화번호) · `REQ-F-004`(전화 걸기)를 `공통`으로 바꾸지 않고 `1차`로 유지했다. 사유 두 가지를 각각 확인했다.

| 사유 | qa 검증 | 판단 |
|---|---|---|
| ① **§1.3의 `공통` 정의 불일치** — `공통` = "1차에 구현하고 2차에 **확장**되는 항목"인데 세 건은 2차 확장 작업이 없다. 2차에 바뀌는 것은 값이 아니라 **출처**이며 그 전환은 `REQ-F-064`(공통)·`TR-04`가, 고정 바 구성은 `REQ-F-003`(공통)이 담당한다 | §1.3 정의 원문, `REQ-F-064`·`REQ-F-003`의 차수(둘 다 `공통`), §10 TR-04·TR-06의 관련 REQ 열을 확인했다. **전환 작업의 소유자가 실제로 `공통` REQ 쪽에 있다.** `차수` 열은 "적용 범위"가 아니라 "구현·전환 작업의 차수"를 뜻한다는 읽기가 문서 전체에서 일관된다 | **타당** |
| ② **M-7상 2차 게이트가 전건을 판정하므로 검증 누락이 없다** | §5.0 M-7 원문("2차 게이트에서는 전 REQ를 판정하되 `공통`은 1차·2차 항목을 모두 본다")과 §7.3 게이트 표("2차 게이트 판정 대상 = 전건, 분모 241")를 대조했다. **`1차` REQ도 2차 게이트에서 다시 판정된다.** 적용 범위 자체는 §9가 따로 규정한다 — `REQ-C-001`은 §9.1(전 영역 공통), `REQ-F-004`·`REQ-C-009`는 §9.2(공개 영역 전체 적용)에 있어 **2차 공개 화면(SCR-020·021·030~034)에도 적용된다는 사실이 기준선에 남아 있다** | **타당** (R1 §5.4의 내 판단과 동일) |

→ **P5 추적에서 빠지는 REQ는 없다.** 영향은 §7.3 집계와 pmo 공수 산정에 한정되며, 그 사실이 §7.3 표 각주에 명시돼 있어 후속 팀이 오해할 여지도 없다.

## 6. 요약

- **Must: 0건 · Should: 0건 · Could: 3건**
- **판정: 승인**

R1에서 "**지적 #1·#2의 대조를 다시 돌리는 것만으로 반영 확인이 끝나며, 두 가지가 맞으면 승인으로 전환한다**"고 적었다. **두 대조를 모두 재실행해 차집합 0건 · §7.3 전칸 일치를 확인했고, Must #3도 네 곳에서 일관되게 반영됐으므로 약속대로 승인한다.** 신규 Could 3건은 게이트를 막지 않으며 문서를 고치지 않아도 qa가 P5 테스트 계획에서 흡수한다.
