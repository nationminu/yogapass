# 리뷰: P2 기획 산출물 3종 v0.2 — qa (R2)

> 이번에도 **문서 검토만** 수행했다(구현물이 없어 도구 실행·측정 없음). 판단 기준은 R1과 같다 — **이 문서만 보고 P5 테스트 케이스를 쓸 수 있는가, Pass/Fail을 다툼 없이 판정할 수 있는가.**
> R1에서 이미 해결된 사항은 다시 문제 삼지 않았고, **v0.2에서 새로 생긴 문제만** 아래 §4에 적었다.

## 1. 총평
- **R1 Must 5건은 전부 해결됐다.** 특히 ① 고정 바를 "여백 확보" 단일 규칙(§3.0)으로 확정하고 전 8화면 와이어프레임에 반영한 점, ② 잠정 기준값을 미루지 않고 지금 넣어(§5.0 M-3, 예약번호 CSPRNG·Base32 8자) TC를 선작성할 수 있게 한 점, ③ REQ-N-R-003(자동 파기)을 "보관 기간 10분 단축 설정에서 파기 실행 → 삭제·기록 확인 / 운영 값은 설정 파일 확인"으로 다시 써 **영구 Block을 실제로 해소**한 점, ④ §9를 유일 기준선으로 세우고 IA §3·화면정의서를 참조로 돌려 세 문서의 SCR↔REQ 불일치를 없앤 점, ⑤ REQ-N-023을 "오픈 판정 기준"으로 재정의해 '행 미노출' 자동 통과 구멍을 막은 점은 검증 관점에서 그대로 쓸 수 있는 수준이다. **§5.3과 §5.0은 P5 테스트 계획의 "검증 범위·한계" 절에 거의 그대로 옮길 수 있다.**
- 다만 v0.2에서 새로 들어온 기준값들끼리 **서로 실행을 막는 상충이 2건** 생겼다. ① REQ-F-003 ①·REQ-N-002의 "폼 입력 중에도 고정 바가 보인다 / 예외 없음"과 §3.0 G-9의 "가상 키보드 활성 중 고정 바 숨김"이 정면으로 어긋나 **모바일 폼 화면에서 기대 결과가 다시 두 개**가 됐고, ② REQ-F-R-023의 "각 50회 조회"는 REQ-F-R-024·§5.0 M-3의 "10분 10회 초과 시 10분 차단" 때문에 **11회째부터 응답이 달라져 시험 자체가 성립하지 않는다**(폼 10분 5회 제한도 같은 이유로 폼 관련 TC 다수를 막는다). 둘 다 문구 1~3줄 수정으로 해소된다.
- 판정은 **수정 요청**이다. Must 2건이 해소되면 남은 Should는 P5 테스트 계획 단계에서 흡수할 수 있으므로 곧바로 승인 가능하다.
