# 리뷰: P3 디자인 산출물 v0.1 (디자인 시스템·페이지 디자인·목업 4종) — developer (R1)

> **검토 범위**: 구현 가능성 · 컴포넌트 재사용성 · 성능 · 접근성 구현 방식 · z-index(D-2) · 1차 구현 착수 준비도 · 목업과 실제 마크업의 정합.
> 디자인 취향(색·여백·톤)은 designer 권한이므로 지적하지 않는다. 2차 상세와 공수 재산정은 범위 밖이다.
> 명령 실행·코드 작성 없이 문서와 목업 HTML만 읽었다.

## 1. 총평

- **1차 기술 설계와 구현을 이 상태로 시작할 수 있다. Must는 0건이다.** §1.6 CSS 변수 블록이 그대로 붙여 쓸 수 있는 형태이고, 구간별 오버라이드(768/1024/1280)와 `prefers-reduced-motion` 처리가 타당하다. 특히 `--body-pad-bottom`을 `calc()` 파생값으로 두고 `≥1280px`에서 `--fixed-bar-h: 0px` 하나만 덮어 전 화면이 따라오게 한 구조는 G-2~G-4·G-9를 한 지점에서 관리하게 해 준다. 화면별 수치가 전부 단일 값으로 닫혀 있어(지도 272/320/400px, Hero min-height 320/420/520px) "범위로 열려 있어 구현이 추측해야 하는" 항목이 없다.
- **대비값을 표본 검증했고 designer 계산이 맞다.** `#0B4F9E`(계산 7.995 → 7.99), `#5A6B7D`(5.477 → 5.48), 오버레이 `rgba(10,37,64,.68)`의 백색 합성색(`#586B7D`, ≈5.50)을 WCAG 상대 휘도 공식으로 직접 재계산해 세 건 모두 소수 둘째 자리까지 일치했다. P5 자동 도구 재측정에서 어긋날 위험은 낮다고 본다.
- **지적 9(Should)·5(Could)는 전부 "구현 단계에서 터질 것을 지금 한 줄로 막는" 성격**이며 게이트를 막지 않는다. 그중 실제로 화면에 보이는 결함이 되는 것은 두 가지다 — ① `:focus-visible` 규칙에 들어간 `border-radius`가 **포커스 순간 요소 모양을 바꾼다**(pill 칩 999px → 6px, #1) ② `--header-h`가 고정값이라 **200% 확대·로고 폴백 시 앵커 진입 위치가 헤더 뒤로 숨는다**(#2). 나머지는 폰트 파일 구성(#5, 성능 90점과 직결)과 정본 확정(#7·#8) 요청이다.
- **z-index 쌓임 순서(D-2)는 designer 판단에 동의한다.** sticky 표 헤더가 사이트 헤더를 덮으면 안 되므로 10 < 20이 맞다. 다만 숫자만으로는 보장되지 않는 조건이 있어 Could #10에 적었다.

## 3. 검토 관점 체크리스트

- [x] **구현 가능성** — §1.6 CSS 변수 블록을 그대로 쓸 수 있는가, 구간별 오버라이드·`prefers-reduced-motion` 처리가 타당한가 → 가능. 결함 1건(#1)과 보완 3건(#2·#3·#4)
- [x] **컴포넌트 재사용성** — 1차 30종이 2차 39화면에서 재사용되는 구조인가, 확장 예고 27종이 1차 토큰을 깨는가 → **깨지 않는다.** 신규 예약 토큰이 5계열뿐이고 컬러·타이포·간격·radius·shadow·z-index·breakpoint는 값 변경 0건이다. compact 스케일(`--space-c1~3`)과 `--z-sticky-table`을 1차에 미리 박아 둔 것이 TR-10 목표에 맞다
- [x] **성능(Lighthouse 90+)** — 1차는 사진 0장·외부 도메인 요청 0건·인라인 SVG·지도 클릭 투 로드이므로 **최대 위험이 한글 웹폰트 하나로 수렴한다**(#5). 히어로 오버레이는 CSS gradient라 비용이 없고, `aspect-ratio`·`width/height`·지도 대체 영역 로드 전후 동일 높이로 **CLS 유발 지점이 설계 단계에서 제거돼 있다**
- [x] **접근성 구현** — 포커스 표시·키보드 탐색·상태 표현이 전부 구현 가능한 방식이다. "색 외 구분 수단" 열을 구현 필수 조건으로 못 박은 것과 장식 이미지 판정 목록(§4.3)을 단일 기준으로 둔 것이 P4 자체 점검·P5 판정을 실행 가능하게 만든다. 보완 2건(#1·#7)
- [x] **z-index 쌓임 순서(D-2)** — 동의. 구현 조건 2가지를 Could #10에 기록
- [x] **1차 구현 착수 준비도** — 기술 설계 착수 가능. 구현 완료 전까지 필요한 미제작 에셋 2종(파비콘·OG) 확인 요청(#9)
- [x] **목업 HTML ↔ 실제 구현(시맨틱·SEO·JS 비활성)** — 랜드마크(`header`/`nav`/`main`/`footer`)·`lang="ko"`·h1 1개·아이콘 `aria-hidden`·아이콘 단독 버튼 `aria-label`이 모두 들어가 있어 그대로 옮겨 쓸 수 있다. 차이 2건(#7·#8), 표기 관행 1건(#14)
