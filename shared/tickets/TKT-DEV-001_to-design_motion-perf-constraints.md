# TKT-DEV-001 CR-002 디자인 고도화 — 구현 금지선·예산과 결정 요청 1건

## 요청 내용

CR-002 디자인 고도화 개정본을 **작성하는 중에** 아래 세 가지를 반영해 주시기 바랍니다.

1. **§A 금지선** — 이대로 명세가 오면 구현이 불가하거나 성능·접근성 기준을 깨는 항목입니다.
2. **§B 예산** — 화면당 전송량·파일 수 상한입니다. 명세에 수치로 넣어 주세요.
3. **§C 결정 요청 1건** — **"사용 굵기를 몇 단 쓰는가"**. 이 답에 따라 폰트 전략과 구현 공수가 달라집니다. **가장 먼저 알려 주시면 폰트 작업을 병렬로 시작할 수 있습니다.**

근거·실측 수치·재현 방법은 전부 `shared/reviews/CR-002_impact_developer.md`에 있습니다. 여기에는 결론만 적습니다.

## 배경·이유

디자인이 다 나온 뒤에 "구현 불가"가 나오면 재작업이 발생합니다. CR-002는 PM 방침이 "최대한 빨리"이므로 재작업 여유가 없습니다.
그래서 designer 개정 작업과 **병렬로** 구현 제약을 먼저 측정했습니다. 현행 사이트의 Lighthouse 증거, 직접 실행한 렌더링 비용 실험 11종, 한글 가변 폰트 용량 실측, MDN 브라우저 지원 데이터(8.1.1)에 근거합니다.

**핵심 오해 하나를 먼저 정정합니다.** Lighthouse 성능 점수는 **로딩 구간만** 측정합니다. 스크롤 애니메이션을 아무리 무겁게 만들어도 점수는 100이 나옵니다. 실제로 이번 실험에서 **스크롤 중 프레임의 25%를 떨어뜨린 구성도 Lighthouse로는 잡히지 않았습니다.** 따라서 "Lighthouse 90+ 유지"는 모션 품질의 안전장치가 아니며, 아래 금지선이 그 역할을 합니다.

### A-3. 모션 토큰에 반드시 추가해야 하는 것

디자인 시스템 §1.4 Motion / §1.6 CSS 변수 블록에 넣어 주세요.

- `--motion-scroll` (기본 1 / 모션 감소 시 0) — 스크롤 연동 애니메이션 진폭 배율
- `--motion-parallax-distance` (기본 15% / 모션 감소 시 0)
- `--motion-kinetic` (기본 1 / 모션 감소 시 0)
- `prefers-reduced-motion: reduce` 블록에 **`animation-timeline: none !important` 규칙 추가**

> **이유**: 현행 `reduce` 블록은 `animation-duration`을 0.01ms로 만드는 방식인데, **스크롤 연동 애니메이션은 진행률이 시간이 아니라 스크롤 위치로 결정되므로 이 방법으로 꺼지지 않습니다.** 지금 구조 그대로 스크롤 연출을 추가하면 모션 민감 사용자에게 그대로 노출됩니다.

## §B 전송 예산 (명세에 수치로 넣어 주세요)

현행 메인 화면 전송량 198KB, 로딩(LCP) 1.06초, 목표 2.5초 기준입니다.

| 항목 | 현행 | **고도화 후 상한** |
|---|---|---|
| 화면당 총 전송 | 198KB | **≤ 280KB** |
| 폰트(화면당) | 160KB (전체의 81%) | **≤ 210KB** |
| CSS(전송 합계) | 24KB | **≤ 39KB** (신규 +15KB) |
| 렌더 차단 CSS 파일 수 | 7개 | **≤ 8개** |
| JS | 2.7KB | **≤ 13KB** (신규 +10KB) |
| 이미지 | 0KB (로고·아이콘 SVG 제외) | **0KB 유지** |
| 스크롤 중 드롭 프레임 | — | **0%** |

**현행 전송량의 81%가 폰트입니다.** 예산에서 실질적으로 다툴 여지가 있는 것은 폰트뿐이고, 그래서 §C가 중요합니다.

## §C 결정 요청 — 사용 굵기를 몇 단 쓰시겠습니까? (회신 요망)

한글 가변 폰트 용량을 실측했습니다(Pretendard v1.3.9 공식 배포본).

- 통짜 가변 파일: **2.06MB** → **어떤 경우에도 사용 불가**
- 현행과 같은 방식으로 분할한 가변본(메인 화면 기준): **181KB** (현행 정적 2단 160KB 대비 +13.5%, 로딩 **+144ms**)
- **정적으로 굵기를 3단 쓰면 메인 245KB** → 이 시점부터 **가변이 26% 더 쌉니다**

| 선택 | 결과 | 구현 공수 |
|---|---|---|
| **굵기 2단 유지** (400·700) | **현행 정적 구성 유지.** 바꿀 이유 없음 | **0일** |
| **굵기 3단 이상** (예: 300·400·600·700, 제목 800 등) | **가변 폰트로 전환.** 전환 후에는 굵기를 몇 단 더 써도 **바이트가 늘지 않습니다** | 1.0~1.5일 |
| **굵기를 연속적으로** 사용 (스크롤·호버에 따라 변화) | **가변 필수** + A-1 #2의 범위 제한 준수 | 1.0~1.5일 |

**회신해 주실 내용**
1. 최종 사용 굵기를 **전부 열거**해 주세요 (예: "400, 600, 700 세 단").
2. **중간 굵기(500·600)를 쓰신다면 별도로 알려 주세요** — 현재 폴백 서체 메트릭 정의가 400·700 두 개뿐이라, 중간 굵기용 정의를 추가하지 않으면 웹폰트 로딩 중 줄바꿈이 흔들립니다(현행 CLS 0이 깨집니다).
3. 제목 전용 **라틴 서체**를 쓰실 계획이 있으면 알려 주세요(라틴 글리프만 5~15KB로 조건부 가능, 한글과 섞일 때 베이스라인 차이 주의).
