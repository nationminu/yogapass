# TKT-DSN-001 REQ-C-L-001의 셀 라벨 폭 근거 수치 정정 요청 ("약 40px" → 실측 48.44px)

## 요청 내용

`planning/02_requirements.md` REQ-C-L-001의 아래 괄호 안 **근거 수치 한 줄만** 정정해 주기를 요청한다.

> 현재: "14px 기준 최대 라벨 폭 약 **40px**("잔여 9+" 기준)로 ②-2의 셀 폭(45.1px) 안에 들어간다"
> 요청: "14px 기준 "잔여 9+"의 실측 폭은 **48.44px**로 셀 폭(45.14px)을 넘는다. `<768px`에서는 **셀 높이를 72px로 올려 라벨을 2줄('잔여' / '9+')로 배치**해 해소한다(디자인 시스템 §3.3). `≥768px`은 셀 폭이 101px 이상이라 1줄로 표기한다."

**문구·규칙·`{n}` 정의는 바꾸지 않는다.** 축약 문구 5종("잔여 {n}"·"마감"·"휴무"·"당일"·라벨 없음)과 "9+" 상한 표기, 접근 이름에 실제 수를 읽는 규칙은 **그대로 유효하고 v1.1 디자인이 그대로 따랐다.**

## 배경·이유

- 2차 디자인 시스템(`design/03_design-system.md` v1.1) 작성 중 CMP-040(월 캘린더) 셀 폭을 실측하면서 확인했다.
- Pretendard 문자 advance 기준(한글 1.0em · 숫자 0.6em · 공백 0.26em)으로 14px에서 계산하면
  `잔여`(14+14) + 공백(3.64) + `9`(8.4) + `+`(8.4) = **48.44px**이다. `--fs-caption` 하한 14px을 지키는 한 1줄로는 45.14px 셀에 들어가지 않는다.
- 글자를 14px 아래로 줄이는 것은 REQ-N-006 ⑤가 명시적으로 금지한다("14px을 줄여서 맞추지 않는다"). 문구를 더 줄이면 REQ-C-L-001이 정한 표기와 달라진다.
- 따라서 **디자인 시스템 §8 D-4가 예고해 둔 흡수안(셀 높이 증가 + 라벨 2줄)** 을 그대로 적용해 셀을 `45.14 × 72px`로 확정했다. 이 값은 REQ-N-006 ②-1(셀 44×44px 이상 · 경계 간격 2px 이상)을 모두 만족한다.
- 정정하지 않으면 **P5에서 "문서 근거값 40px ↔ 구현 48.44px"** 이 어긋난 것으로 보여 불필요한 결함 확인이 생긴다. 실제 구현·판정에는 문제가 없다.

**참고 — 같은 맥락의 v1.1 정정 1건(기획 수정 불요)**: 디자인 시스템 v1.0이 쓰던 "캘린더 좌우 패딩 12px → 셀 폭 46.28px"을 **컨테이너 패딩 16px → 45.14px**로 되돌렸다. REQ-N-006 ②-2의 실측 기준값 45.1px과 일치시키기 위함이며, ②-2가 "계산식이 기준"이라고 명시해 두었으므로 **기획 문서 수정은 필요 없다.**

## 완료 조건

- [ ] REQ-C-L-001의 근거 수치 문장이 실측값(48.44px)과 2줄 배치 전제로 갱신된다.
- [ ] 축약 문구 5종·`{n}` 정의·"9+" 상한·접근 이름 규칙은 **변경되지 않는다**(변경되면 디자인 재작업이 생기므로 designer에게 먼저 알린다).
- [ ] 다른 문서(IA·화면정의서)에 "약 40px"이 복제되어 있지 않은지 확인한다.
